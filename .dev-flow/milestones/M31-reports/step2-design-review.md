# Step 2: 设计核对报告

## 审查范围

M31 里程碑文档 vs 产品文档（PRODUCT.md）。

## 审查维度

### 1. 产品定位一致性

| 检查项 | 结论 | 说明 |
|--------|------|------|
| 单用户、自托管 | ✅ | S3 增强不引入多用户/RBAC |
| 深色优先 | ✅ | 纯 UI 增强，遵循现有主题 |
| 不引入外部 SaaS | ✅ | 使用 AWS SDK 原生能力 |

### 2. 功能边界

| 检查项 | 结论 | 说明 |
|--------|------|------|
| S3 连接参数 | ✅ | PRODUCT.md 3.4 资源创建向导已包含 S3 表单 |
| Storage Class 列 | ✅ | PRODUCT.md 3.8 明确要求「Storage Class·ACL（S3）」 |
| Presigned URL | ✅ | S3 标准能力，符合文件管理场景 |
| Multipart resume | ✅ | PRODUCT.md 3.8 要求「S3 multipart 续传」 |
| 不做 ACL 管理 | ✅ | 合理范围控制，避免里程碑过大 |
| 不做 Bucket 策略 | ✅ | 合理范围控制 |

### 3. 架构一致性

| 检查项 | 结论 | 说明 |
|--------|------|------|
| 复用 FileConnector trait | ✅ | 扩展而非替换现有架构 |
| FileConnectRequest 复用 | ✅ | S3 字段已存在于请求结构 |
| 前端 FilesPage 复用 | ✅ | 条件列 + 条件字段，不新建页面 |

### 4. 子任务拆分

| 检查项 | 结论 | 说明 |
|--------|------|------|
| 粒度合理 | ✅ | 4 个子任务，每个 1-2 commit |
| 依赖关系清晰 | ✅ | 子任务 1→2→3→4 无循环依赖 |
| 前后端覆盖 | ✅ | 每个子任务同时涉及前后端 |

### 5. 接口设计

| 检查项 | 结论 | 说明 |
|--------|------|------|
| FileEntry 扩展 | ✅ | `storage_class: Option<String>` 向后兼容 |
| Presigned URL API | ✅ | 独立端点，不影响现有上传/下载 |
| Multipart resume | ✅ | 扩展上传端点，可选参数 |

## 结论

✅ M31 里程碑文档设计合理，与产品文档一致，子任务拆分粒度适当。
