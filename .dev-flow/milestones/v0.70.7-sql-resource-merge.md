# v0.70.7: SQL 资源模型合并（单一 SQL 资源 + 连接时自动识别 dialect）

## Context
v0.70.6 已完成「统一 Hub↔Agent 隧道架构」：SSH/SQL/Redis/文件协议在 agent 模式下由 Agent 私网内终结，Hub 退化为传输隧道。本阶段在此之上做资源模型收敛：当前 MySQL / PostgreSQL / SQLite 是**三个并列的资源类型**（各自 protocol、各自连接树图标/色值、各自创建表单），但后端 `SqlConnector` 抽象早已方言无关（`rex_mysql`/`rex-postgresql`/`rex-sqlite` 各实现同一 trait），三者仅由 `db_type` 字符串分支。把三者合并为单一「SQL」资源，并在**连接时自动识别 dialect**，可消除重复 UI、降低用户选择负担，且为将来拓展同族方言（MariaDB/ClickHouse 等）预留探测表位。

版本类型：minor（新增功能，向后兼容——旧资源 in-place 升级，无破坏性变更）

## 产品边界
**做什么**
- 用单一「SQL」资源替代并列的 MySQL / PostgreSQL / SQLite 三种资源。
- 用户创建时只选「SQL」并填连接信息；连接时自动识别 dialect（SQLite 看 host/file_path；MySQL↔PostgreSQL 用端口预判 → 双线缆协议握手回退 → `SELECT VERSION()` 确认），识别后回写资源，之后直连秒开。
- 允许用户在创建时显式选 subtype（mysql/postgresql/sqlite）以跳过探测（兼容旧行为与精确控制）。

**不做什么**
- **不新增任何数据库方言**：本里程碑仅支持 MySQL / PostgreSQL / SQLite 三种。MariaDB / ClickHouse / Oracle / SQL Server 等**不在范围**——探测表预留扩展位，但本次不实现、不引入新依赖。
- 不改变 SQL 控制台的交互/能力（表设计器、DDL、导出向导、AI 助手等 Navicat 对标行为不变）。
- 不改变 Redis / 文件(S3/SFTP) / SSH / SIP 资源模型。
- 不引入多用户 / RBAC / 企业协作概念（AGENTS.md 硬性约束）。

## 子任务详细设计

### 1 资源模型收敛：单一「SQL」+ db_type: Option + 探测回写

- **功能目标**：在 `Resource` 模型上引入可选 `db_type`，使三种 SQL 资源统一为 `protocol = "sql"`；探测出的 dialect 回写到 `db_type`。
- **文件结构**
  - `crates/rex-hub/src/models.rs`：`Resource` 增加 `pub db_type: Option<String>`（位于 `protocol` 之后）。
  - `crates/rex-hub/src/db.rs`：资源 `INSERT`/`UPDATE`/`SELECT` 映射增加 `db_type` 列（新增 `resources.db_type` 列，迁移脚本见子任务5）。`ResourceConnInfo`（`resource_conn.rs`）增加 `db_type: Option<String>` 透传。
  - `crates/rex-hub/src/resource_api.rs`：资源创建/更新接受 `db_type`（缺省 `None`）；返回体含 `db_type`。
- **接口设计**：资源 CRUD 请求/响应新增可选 `db_type` 字段；旧客户端不传时后端按 `None` 处理（向后兼容）。
- **后端流程**：保存资源时 `protocol` 写 `"sql"`，`db_type` 取用户显式值或 `None`；连接时（子任务2）解析 dialect，成功后回写 `db_type`。
- **测试标准**：`models.rs` / `db.rs` 单测覆盖「db_type=None 资源可存可取」「db_type 解析与回写」。
- **提交信息**：`feat(hub): add optional db_type to Resource, unify SQL protocol (v0.70.7 #1)`

**设计原则**：db_type 缺省即"待探测"；显式值优先。迁移脚本非破坏性（旧 protocol 值整体搬入 db_type）。

### 2 连接入口 dialect 探测

- **功能目标**：db_type 缺省时，连接入口自动判定 dialect，且 Hub 直连与 Agent 隧道两侧逻辑对称。
- **文件结构**
  - `crates/rex-hub/src/sql_api.rs`：`connect` 在 `db_type` 为空时进入探测分支。
  - `crates/rex-agent/src/agent_sql.rs`：`connect_by_type` 增加"未知 → 探测"路径；`handle_connect_sql` 复用。
  - `crates/rex-common/src/agent_proto.rs`：`AgentSessionMsg::SessionOpened` 增加可选 `db_type` 字段（探测结果由 Agent 回传 Hub 持久化；向后兼容可选字段）。
- **探测算法（两侧共用同一规则）**：
  1. `db_type` 已显式（mysql/postgresql/sqlite）→ 直接用。
  2. 无 host 或 `file_path` 存在 → SQLite。
  3. 否则按端口预判（3306→MySQL，5432→PostgreSQL），尝试对应连接器；握手报协议错（线缆协议不匹配）则回退试另一种。
  4. 握手成功后执行 `SELECT VERSION()`：MySQL 回 `8.0.x`、PostgreSQL 回 `PostgreSQL 15.x` → 确认 dialect，消除歧义。
  5. 两者均失败 → 返回「无法识别 dialect，请在创建时指定 subtype」。
- **后端流程**：探测成功 → 建立连接 → 直连模式直接 `UPDATE resources SET db_type=?`；agent 模式由 `SessionOpened.db_type` 触发 Hub 回写。
- **测试标准**：`agent_sql.rs` + `sql_api.rs` 单测覆盖「MySQL 协议连 PG 服务端失败并回退」「VERSION() 字符串解析」「SQLite 经 file_path 判定」。
- **提交信息**：`feat(sql): auto-detect dialect at connect (hub + agent symmetric) (v0.70.7 #2)`

**设计原则**：探测仅发生在 db_type 缺省时；识别后**回写一次**，后续连接读缓存、无额外往返。当前仅 MySQL/PostgreSQL/SQLite 三条分支，探测表结构为将来同族方言留位但不实现。

### 3 前端连接树 / 创建向导合并为单「SQL」

- **功能目标**：连接树、仪表盘、创建向导把三种 SQL 合并为单「SQL」类型，按探测/显式 dialect 着色与显示图标。
- **文件结构**
  - `packages/rex-console-web/src/features/resource/protocols.ts`：新增 `sql` 协议条目（图标 `dB`、主色 `#58A6FF`、名称「SQL」）；新增 `subtypeMeta` 映射 mysql/postgresql/sqlite → 各自色值/图标，供按 dialect 着色。
  - `packages/rex-console-web/src/features/resource/WizardModal.vue`：删除 mysql/postgresql/sqlite 三个独立选项（L31-34），改为单个 `sql` 选项；新增可选 subtype 下拉（默认空=自动识别），端口默认按 subtype 或 3306。
  - `packages/rex-console-web/src/pages/EnvironmentDetailPage.vue`：资源列表/编辑的 `['mysql','postgresql'].includes(protocol)` 等分支合并为 `protocol === 'sql'`，色值/Badge 按 `db_type` 取 `subtypeMeta`。
  - `packages/rex-console-web/src/pages/DashboardPage.vue`：协议→色映射（L38-39）增加 `sql`。
  - `packages/rex-console-web/src/features/workspace/ResourceProperties.vue`：端口默认（L124）、彩色点（L220）、表单分支（L164/202/256/268）按 `sql` + subtype 调整。
  - `packages/rex-console-web/src/composables/useTabs.ts`：`TabProtocol` 增加 `'sql'`（L3）。
- **交互设计**：左侧连接树「SQL」一类，展开后按 dialect 图标区分；创建向导先选「SQL」，可选选 MySQL/PostgreSQL/SQLite，留空则连接时自动识别。
- **测试标准**：`WizardModal` 单测覆盖「选 SQL + 空 subtype 可提交」「选 SQL + subtype 端口预填」；类型检查通过。
- **提交信息**：`feat(fe): merge SQL types into single SQL resource in tree/wizard (v0.70.7 #3)`

### 4 前端 SQL 控制台按实际 dialect 路由

  - `packages/rex-console-web/src/features/sql/SqlNavTree.vue`：图标/类型标签按 `dbType` 取 `subtypeMeta`。
- **后端流程**：无（前端纯路由）。
- **测试标准**：`bun run type-check` 通过；控制台对 mysql/postgresql/sqlite 资源渲染与合并前一致。
- **提交信息**：`feat(fe): route SQL console by detected dialect (v0.70.7 #4)`

### 5 旧资源 in-place 升级迁移

- **功能目标**：已存在的 mysql/postgresql/sqlite 资源无破坏升级为 `protocol='sql'` + `db_type=<旧protocol>`。
- **文件结构**
  - `crates/rex-hub/src/db.rs`（或迁移模块）：`ALTER TABLE resources ADD COLUMN db_type TEXT;`；`UPDATE resources SET db_type=protocol, protocol='sql' WHERE protocol IN ('mysql','postgresql','sqlite');`

- **测试标准**：单测/集成验证「迁移后旧资源仍可直连 / agent 模式连接，dialect 正确」。
- **提交信息**：`feat(hub): migrate mysql/postgresql/sqlite resources to unified sql (v0.70.7 #5)`
