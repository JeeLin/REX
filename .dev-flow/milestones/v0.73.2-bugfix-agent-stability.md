## 子任务详细设计

### 1 修复 Agent 模式 SQL 连接测试 unsupported protocol

- **功能目标**：Agent 侧实现 SQL 协议的 connect/tunnel 处理
- **文件结构**：
  - 修改：`crates/rex-agent/src/agent_sql.rs`（新增 SQL connect handler）
  - 修改：`crates/rex-agent/src/agent_ws.rs`（路由 SQL connect 请求）
- **问题分析**：v0.70.6 隧道架构下沉时，SSH/Redis/S3 等协议在 Agent 侧有 connect handler，但 SQL 被遗漏
- **修复方案**：在 `agent_ws.rs` 的 connect 路由中添加 SQL 协议分支，调用 `agent_sql` 模块处理
- **测试标准**：Agent 模式 SQL 连接测试返回 `{"ok":true}`
- **提交信息**：`fix: add SQL protocol handler in agent tunnel`

### 2 修复 Agent 模式 SQL 查询超时

- **功能目标**：Hub 的 SQL session 正确关联到 Agent tunnel，查询请求能转发到 Agent
- **文件结构**：
  - 修改：`crates/rex-hub/src/sql.rs`（session → tunnel 关联逻辑）
  - 修改：`crates/rex-hub/src/agent_ws.rs`（tunnel data 路由）
- **问题分析**：`/api/sql/connect` 通过 Agent 成功建立 session，但后续 `/api/sql/databases` 查询时 Hub 找不到对应的 Agent tunnel，导致 timeout
- **修复方案**：SQL session 创建时记录 agent_id，查询时通过 agent_id 找到对应 tunnel 转发请求
- **测试标准**：Agent 模式 SQL 查询正常返回结果
- **提交信息**：`fix: route SQL queries through agent tunnel`

### 3 修复 Windows Agent 更新 rename 失败

- **功能目标**：Windows 下 supervisor 能成功替换正在运行的 exe
- **文件结构**：
  - 修改：`crates/rex-agent/src/supervisor.rs`（apply_update 函数）
- **问题分析**：Windows 不允许 rename/delete 正在运行的可执行文件（os error 5）
- **修复方案**：先 rename 当前 exe 为 .old → rename staged 为当前 → 下次启动时清理 .old
- **测试标准**：Windows 下更新后新版本生效
- **提交信息**：`fix: handle Windows exe rename lock in supervisor`

### 4 修复 Agent 更新重复触发

- **功能目标**：Agent 启动后只触发一次更新检查
- **文件结构**：
  - 修改：`crates/rex-agent/src/agent_ws.rs`（移除 HubMsg::Update 处理）
  - 修改：`crates/rex-agent/src/supervisor.rs`（新增后台更新检查任务）
- **问题分析**：当前设计错误地把更新检查+下载塞进了 worker，supervisor 只做 rename。Hub 每次心跳都推送更新命令导致重复
- **修复方案**：worker 不再处理 HubMsg::Update；supervisor 启动后台定时任务检查 GitHub Release，发现新版本后下载+exit(42)
- **测试标准**：Agent 启动后只出现一次 update 日志
- **提交信息**：`fix: move update check from worker to supervisor`
