# 0.83.1: 工作空间交互可靠性

## Context
0.83.0 完成了前端 UI/UX 重新设计（设计系统、响应式、无障碍）。`AGENTS.md` 已知问题清单中仍有若干核心操作界面的交互缺陷未修复，其中直接影响日常使用的三项集中在工作空间：

- #4 分屏和拖拽基本不可用
- #3 快捷键展示异常（landing page `Ctrl+K` / `Ctrl+N` / `Alt+1~5` / `F1`）
- #5 SSH 终端复制粘贴与浏览器 `Ctrl+C/V` 冲突

本阶段为纯修复（patch），聚焦工作空间这一核心操作面，不改变任何后端 API 或数据模型，不涉及新功能。修复后让分屏拖拽、全局快捷键、终端复制粘贴达到「可用且行为可预期」。

## 产品边界
本阶段做什么：
- 分屏拖拽：标签拖入面板（填充 / 换位）、标签栏内重排、拖拽视觉反馈
- 全局快捷键：统一两套 keydown 处理逻辑，修正触发与展示异常
- SSH 终端复制粘贴：消除与浏览器默认 `Ctrl+C/V` 的冲突

本阶段不做什么：
- 新功能开发
- 后端 API 变更
- 数据库 schema 变更
- 其他已知问题（Agent 在线状态 #7、SQLite 自动连接等已在 0.81/0.82 修复）

## 子任务详细设计

### 1 分屏拖拽修复
- **功能目标**：分屏模式下，拖拽标签到面板可正确「填充空面板」或「与已占用面板换位」，标签栏内拖拽可重排顺序；全程有清晰视觉反馈。
- **文件结构**（修改）：
  - `packages/rex-console-web/src/pages/Workspace.vue`（面板区域 DnD：`onPanelDragOver`/`onPanelDrop`/`onPanelDragLeave` ~`:425-448`；`dragId`/`dragOverPanel` 状态）
  - `packages/rex-console-web/src/features/workspace/TabBar.vue`（标签 DnD：`onDragStart`/`onDragOver`/`onDrop`/`onDragEnd` ~`:60-99`；`dragging`/`drag-over-left`/`drag-over-right` 类）
  - `packages/rex-console-web/src/features/workspace/useTabs.ts`（`moveTabToPanel`/`swapPanels`/`reorderTab` ~`:127-170`）
- **接口设计**：保持现有函数签名不变（`moveTabToPanel(id, panelIndex)`、`swapPanels(id1, id2)`、`reorderTab(fromId, toId)`），仅修正调用时机与边界条件。
- **交互设计**（参考 `Workspace.vue` 现有模板：面板 `layout-drop-zone` 虚线高亮、源标签 `opacity:0.5`）：
  - 拖入**空面板** → `moveTabToPanel(dragId, panelIndex)`，自动填充。
  - 拖入**已占用面板** → `swapPanels(dragId, existingTab.id)`，交换两面板内容。
  - **单面板模式**禁用面板拖拽（已 `currentLayout==='single'` 守卫）。
  - 标签栏内拖拽 → 按落点左右半区决定 `reorderTab` 插入位置。
- **后端流程**：无。
- **测试标准**：
  - 单测 `useTabs`：`moveTabToPanel` 改变 `panelIndex`；`swapPanels` 正确交换两者 `panelIndex`；`reorderTab` 在 `from==to` 或缺失 id 时为空操作（no-op）。
  - 组件/集成测试（vitest + @testing-library）：在 quad/left-right 布局下，模拟 `dragstart`/`drop`，断言目标面板 `panelIndex` 与源标签顺序符合预期；`layout-drop-zone` 类在 `dragover` 时挂载、`dragleave`/`drop` 后移除。
- **提交信息**：`fix(ws): repair panel drag-and-drop swap/fill and reorder`

### 2 全局快捷键修复
- **功能目标**：统一全局快捷键处理，消除「两套独立 keydown 监听」导致的触发/展示异常；landing page 与快捷键面板（F1）正确展示 `Ctrl+K` / `Ctrl+N` / `Alt+1~5` / `F1` 等。
- **文件结构**（修改）：
  - `packages/rex-console-web/src/layouts/AppLayout.vue`（`onGlobalKeyDown` ~`:482-500`，注册 `Ctrl+K`/`Ctrl+N`/`F1` 并 `dispatchEvent('rex:shortcut')`）
  - `packages/rex-console-web/src/pages/Workspace.vue`（`onKeyDown` ~`:735-772`，处理 `Alt+1~5`/`Ctrl+1~9`/`F11`/Esc，并 `onShortcut` 监听 `rex:shortcut`）
  - `packages/rex-console-web/src/components/CommandPalette.vue`（Ctrl+K 面板，已具备焦点陷阱与 Esc 关闭）
- **接口设计**：收敛为单一全局入口。建议：仅保留 `AppLayout.vue` 作为全局 keydown 唯一监听者，按 `detail` 派发意图事件；`Workspace.vue` 只响应 `rex:shortcut` 事件，不再自行 `window.addEventListener('keydown', onKeyDown)`。避免同一按键被两个监听器重复处理。
- **交互设计**（参考产品文档 §3.5 / §5）：
  - 输入框 / textarea 聚焦时（如命令面板搜索框）不拦截快捷键，避免与输入冲突。
  - 模态/面板打开时，`Esc` 优先关闭最上层（命令面板 → 连接菜单 → 快捷键面板），已有实现需验证顺序。
  - 快捷键面板（F1）内容与实际绑定一致：`Ctrl+K` 全局搜索、`Ctrl+N` 新建连接、`Alt+1~5` 布局、`F11` 全屏、`F1` 帮助。
- **后端流程**：无。
- **测试标准**：
  - 在 `AppLayout.vue` 上下文中挂载，dispatch 真实 `KeyboardEvent`（带 `ctrlKey`/`key`/`altKey`），断言派发的 `rex:shortcut` `detail` 正确（`command-palette`/`new-connection`/`shortcuts-panel`）。
  - 断言焦点在 input 时不触发全局快捷键。
  - 快捷键面板渲染出 `Ctrl+K` / `Ctrl+N` / `Alt+1~5` / `F1` 对应条目且文案与绑定一致（可对照 i18n 键）。
- **提交信息**：`fix(ws): unify global keyboard shortcut handling and fix display`

### 3 SSH 终端复制粘贴修复
- **功能目标**：SSH 终端内 `Ctrl+C`/`Ctrl+V` 行为清晰、不与浏览器默认冲突。
- **文件结构**（修改）：
  - `packages/rex-console-web/src/features/workspace/panels/WorkspaceTerminal.vue`（`attachCustomKeyEventHandler` ~`:283-310`；`paste` 事件监听 ~`:317-xxx`；`handlePaste`/`copyWithFallback`）
- **接口设计**：沿用 `terminal.attachCustomKeyEventHandler` 返回值约定（`true`=交给终端/`false`=已处理并吞掉默认）。
- **交互设计**（参考产品文档 §3.6 状态栏 `Ctrl+Shift+C 复制`、右键菜单）：
  - `Ctrl+V`：吞掉默认，触发浏览器原生 paste → 经 `paste` 事件监听转发到 WebSocket（保持当前转发逻辑）。
  - `Ctrl+C`：有选中文本 → 复制并吞掉默认（不发送 SIGINT）；无选中文本 → 交还终端发送 `SIGINT`（保留 `Ctrl+Shift+C` 强制复制）。
  - 右键菜单「复制 / 粘贴」仍独立可用。
  - 验证：在终端内选中文本后 `Ctrl+C` 只复制不中断；无选中时 `Ctrl+C` 发送中断；`Ctrl+V` 粘贴远端。
- **后端流程**：无（paste 经既有 `terminal.input` WebSocket 通道转发）。
- **测试标准**：
  - 针对 `attachCustomKeyEventHandler` 的回调逻辑单测：构造 `KeyboardEvent`，断言 `Ctrl+C` 有/无选中时的返回值与副作用（复制调用 / 不复制）；`Ctrl+V` 返回 `false`；`Ctrl+Shift+C` 强制复制返回 `false`。
  - 通过 `vi.fn()` mock `terminal.getSelection` 与 `copyWithFallback`，断言调用时序。
- **提交信息**：`fix(terminal): resolve Ctrl+C/V copy-paste conflict with browser`
