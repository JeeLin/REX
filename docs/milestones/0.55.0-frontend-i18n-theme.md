# 0.55.0: 前端 i18n 与主题系统优化

## Context

0.54.0 完成了仪表盘增强与快速连接优化。经过代码探索发现前端存在以下可优化点：
- i18n 存在大量重复 key（`ws.workspace.*` 与 `ws.*` 几乎完全重复）
- SqlSidebar.vue 有一处硬编码中文字符串未国际化
- 系统主题模式缺少 `matchMedia` 监听器，系统偏好变化时不会自动切换
- Dashboard 快速连接"在新标签中打开"与普通连接行为完全相同（bug）
- settings.ts 使用 plain `reactive()` 而非 Pinia store，与其他 store 架构不一致

版本类型：patch（bug 修复 + 重构，无新功能）

## 产品边界

**做什么：**
- 清理 i18n 重复 key，消除约 200 行冗余翻译
- 修复 SqlSidebar.vue 硬编码中文字符串
- 为系统主题模式添加 `matchMedia` 监听器
- 修复 Dashboard "在新标签中打开" 行为
- 将 settings.ts 重构为 Pinia store

**不做什么：**
- 不添加新的产品功能
- 不修改后端 API
- 不改变现有用户可见行为（仅修复 bug 和重构）

## 子任务详细设计

### 1 i18n 重复 key 清理

- **功能目标**：消除 `ws.workspace.*` 与 `ws.*` 之间的重复 key，统一使用 `ws.*` 命名空间
- **文件结构**：
  - 修改 `packages/rex-console-web/src/i18n/zh.ts`
  - 修改 `packages/rex-console-web/src/i18n/en.ts`
  - 修改 `packages/rex-console-web/src/features/workspace/` 下引用这些 key 的组件
- **功能点**：
  - 识别 `ws.workspace.empty`、`ws.workspace.shortcuts`、`ws.workspace.nav`、`ws.workspace.actions`、`ws.workspace.fullscreen` 与对应顶层 `ws.*` key 的重复
  - 统一保留 `ws.*` 命名空间，删除 `ws.workspace.*` 冗余 key
  - 更新所有引用 `ws.workspace.*` 的组件到 `ws.*`
  - 确保 zh.ts 和 en.ts 的 key 数量保持一致
- **测试标准**：
  - zh.ts 和 en.ts key 数量一致且无重复
  - 所有 `ws.workspace.*` 引用已更新
  - `bun run type-check` 通过
  - `bun run lint` 通过
- **提交信息**：`refactor: consolidate duplicate i18n keys in workspace namespace`

### 2 系统主题自动切换 + SqlSidebar 国际化修复

- **功能目标**：系统主题模式下监听系统偏好变化自动切换；修复 SqlSidebar 硬编码中文
- **文件结构**：
  - 修改 `packages/rex-console-web/src/stores/user.ts`
  - 修改 `packages/rex-console-web/src/features/sql/SqlSidebar.vue`
  - 修改 `packages/rex-console-web/src/i18n/zh.ts`（新增 key）
  - 修改 `packages/rex-console-web/src/i18n/en.ts`（新增 key）
- **功能点**：
  - `applyTheme('system')` 时添加 `matchMedia('(prefers-color-scheme: dark)')` 事件监听
  - 系统偏好变化时自动切换 `data-theme` 属性
  - 组件卸载时移除监听器（防内存泄漏）
  - SqlSidebar.vue 第 413 行 `'新建表'` 改为 `t('sql.sidebar.newTable')`（或类似 key）
  - 新增对应的 i18n key（zh: "新建表"，en: "New Table"）
- **测试标准**：
  - 系统主题模式下切换 OS 偏好，页面自动切换深色/浅色
  - SqlSidebar 新建表 tab 名称跟随语言设置
  - `bun run type-check` 通过
- **提交信息**：`feat: add system theme auto-switch and fix i18n leak in SqlSidebar`

### 3 Dashboard "在新标签中打开" bug 修复

- **功能目标**：修复 Dashboard 快速连接右键菜单"在新标签中打开"与普通连接行为相同的问题
- **文件结构**：
  - 修改 `packages/rex-console-web/src/pages/Dashboard.vue`
- **功能点**：
  - 分析 `onQuickConnectCtx` 中"连接"和"在新标签中连接"的实现
  - "在新标签中连接"应使用 `addTab` + `router.push('/workspace')` 而非复用 `connectToResource`
  - 或者：如果当前 `connectToResource` 已经处理了标签去重，则"在新标签中连接"需要跳过去重逻辑，强制打开新标签
  - 参考 `useProtocol.ts` 中 `connectToResource` 的实现，确保两个菜单项行为不同
- **测试标准**：
  - "连接"跳转到已有标签（去重）
  - "在新标签中连接"强制打开新标签
  - `bun run type-check` 通过
- **提交信息**：`fix: dashboard quick connect "open in new tab" now opens a new tab`

### 4 settings.ts 重构为 Pinia store

- **功能目标**：将 settings.ts 从 plain `reactive()` 重构为 Pinia `defineStore`，与 auth/user/agent store 保持一致
- **文件结构**：
  - 重构 `packages/rex-console-web/src/stores/settings.ts`
  - 更新所有引用 `terminalSettings`、`securitySettings`、`appearanceSettings` 的组件
- **功能点**：
  - 将 `terminalSettings`、`securitySettings`、`appearanceSettings` 合并或分别定义为 Pinia store
  - 保持现有的 localStorage 持久化和 debounce 后端同步逻辑
  - 保持现有的 `updateXxxSetting()` 函数签名，避免大规模组件改动
  - 使用 Composition API (setup) 模式，与其他 store 一致
- **测试标准**：
  - 所有设置页面功能正常
  - `bun run type-check` 通过
  - `bun run lint` 通过
- **提交信息**：`refactor: convert settings to pinia store for consistency`
