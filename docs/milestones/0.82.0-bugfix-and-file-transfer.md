## 子任务详细设计

### 1 SQLite 自动连接优化
- **问题描述**：SQLite 虽能自动连接，但存在以下问题：
  1. Tab 栏在 800ms 后伪造 'online' 状态，不反映实际连接状态
  2. 自动连接错误被静默吞掉 (.catch(() => {}))
  3. WebSocket 断开后无自动重连（终端有指数退避重连）
- **功能目标**：改善 SQLite 连接体验，正确显示连接状态
- **文件结构**：
  - 修改：`packages/rex-console-web/src/features/sqlite/useSqliteSession.ts`
  - 修改：`packages/rex-console-web/src/features/workspace/useTabs.ts`
  - 修改：`packages/rex-console-web/src/features/workspace/panels/WorkspaceSqlite.vue`
- **交互设计**：
  - 连接中显示 loading 状态
  - 连接失败显示错误提示，支持重试
  - WebSocket 断开时自动重连（指数退避）

### 2 文件传输并发数量控制
- **问题描述**：当前无并发控制，每个传输任务无限制地启动 tokio task
- **功能目标**：实现基于 Semaphore 的并发限制，支持可配置的最大并发数
- **文件结构**：
  - 修改：`crates/rex-hub/src/transfer.rs`（添加 Semaphore 和并发控制）
  - 修改：`crates/rex-transfer/src/task.rs`（TransferManager 添加并发限制）
  - 修改：`packages/rex-console-web/src/features/files/TransferQueuePanel.vue`（显示等待状态）
  - 修改：`packages/rex-console-web/src/api/settings.ts`（读取并发配置）
- **接口设计**：
  - 后端：TransferManager 添加 `max_concurrent: Arc<Semaphore>` 字段
  - 后端：execute_transfer 在执行前 acquire permit，完成后 release
  - 前端：传输队列显示「等待中」状态的任务
- **交互设计**：
  - 传输任务状态：transferring（传输中）/ waiting（等待中）/ completed / failed
  - 显示当前并发数 / 最大并发数
  - 默认最大并发数：3

### 3 sqlx-postgres future-incompat 警告修复
- **问题描述**：sqlx-postgres 0.8.0 存在 never type fallback 问题，未来 Rust 版本将拒绝编译
- **功能目标**：升级 sqlx 到 0.8.6，消除警告
- **文件结构**：
  - 修改：`Cargo.lock`（升级 sqlx 依赖）
- **修复方案**：运行 `cargo update -p sqlx`，从 0.8.0 升级到 0.8.6（semver 兼容）
- **验证方法**：
  - `cargo check --workspace` 无 future-incompat 警告
  - `cargo test --workspace` 通过
