## 子任务详细设计

### 1 SQLite 连接失败错误提示修复

- **功能目标**
  后端 `ws_sqlite.rs::classify_sqlite_error` 已返回用户可读的错误（如「数据库文件不存在: /path/db.db」）。但前端 `useSqliteSession.ts` 中，WebSocket `onclose` 会用 "Connection lost, reconnecting..." 覆盖 `error.value`，导致用户永远看不到真实错误。

- **文件结构**
  - 修改：`packages/rex-console-web/src/features/sqlite/useSqliteSession.ts`
  - 修改：`packages/rex-console-web/src/features/sqlite/useSqliteSession.ts` 单元测试（如存在）

- **根因分析**
  - `handleServerMsg` 在收到后端 `error` 类型消息时设置 `error.value = msg.message`（正确）
  - 但后端发送 error 后会立即关闭 WebSocket，触发 `onclose`
  - `onclose` 无条件设置 `error.value = "Connection lost, reconnecting in Xs..."`，覆盖真实错误
  - 且 `onclose` 在 `ws && reconnectAttempts < MAX` 时会自动重连，进一步干扰错误展示

- **修复方案**
  1. 引入 `closedByError` 标志：当 `handleServerMsg` 处理 `error` 消息时，标记连接因错误关闭
  2. `onclose` 中：若 `closedByError` 为真，保留 `error.value`（不覆盖），且不触发自动重连
  3. `onclose` 中：若正常关闭（用户主动 disconnect 或重连耗尽），按原逻辑处理
  4. `connect()` 开始时重置 `closedByError = false`

- **交互设计**
  错误展示沿用现有 `WorkspaceSqlite.vue` 的 `.sqlite-error` 区块（`v-if="session.error.value"`），无需改动前端组件。

- **测试标准**
  - 单元测试：模拟后端发送 `{type:'error', message:'数据库文件不存在'}` 后关闭，断言 `error.value` 保持为原始消息而非 "Connection lost"
  - 手动验证：连接一个不存在的 SQLite 路径，页面显示具体错误而非重连提示

- **提交信息**
  `fix: preserve SQLite connection error message in frontend`

### 2 Agent 未配置状态显示修正

- **功能目标**
  修复 DB 中 Agent `status` 字段不可信导致的虚假在线显示。`upsert_agent`/`update_heartbeat` 硬编码 `status='online'`，但 Hub 重启或 WS 异常断开时 DB 残留 `online`，导致未真正连接的 Agent 误显在线。基于 `last_seen_at` 新鲜度动态计算真实状态，符合 PRODUCT.md 的两态模型（🟢 在线 / ⚫ 离线）。

- **文件结构**
  - 修改：`crates/rex-hub/src/agent.rs`（`list_agents`：用 `last_seen_at` 新鲜度覆盖 DB `status`）
  - 修改：`crates/rex-hub/src/env.rs`（`list_environments`：agent_online 查询同步基于 `last_seen_at`）
  - 修改：`packages/rex-console-web/src/features/agents/AgentCard.vue`（online 状态下 config_json 为空时显示「⚠ 未配置」提示文字）
  - 修改：`packages/rex-console-web/src/features/agents/AgentStatusPanel.vue`（同上）

- **根因分析**
  - `agent.rs::upsert_agent` / `update_heartbeat` 硬编码 `status='online'`，`ws.rs` 断开时调用 `set_agent_status(aid, "offline")`
  - Hub 重启后 DB 残留 `online` 记录，无代码将过期 Agent 标记 offline
  - `list_agents` 仅当 `token_hash != env_token_hash` 时改 offline，未考虑「从未连接」或「Hub 重启后残留」场景

- **修复方案**
  1. 后端 `list_agents`：查询时比较 `last_seen_at` 与当前时间；超过 3 分钟（两次心跳间隔）视为 `offline`，覆盖 DB 中的 `status` 字段
  2. 后端 `list_environments` 中 `agent_online` 子查询同理：基于 `last_seen_at` 新鲜度判定
  3. 前端仅在 Agent 已在线（`status==='online'`）且 `config_json` 为空时，显示「⚠ 未配置」小字提示，不引入第三状态，保持 PRODUCT.md 两态模型
  4. 后端单元测试：`last_seen_at` 过旧的 Agent 返回 `offline`，`last_seen_at` 新鲜的 Agent 返回 `online`

- **交互设计**
  沿用现有 `AgentCard.vue` / `AgentStatusPanel.vue` 的两态结构（online 绿色 / offline 灰色），仅在 badge 旁追加一行灰色小字「未配置」作为补充信息。

- **测试标准**
  - 后端单元测试：`list_agents` 对 `last_seen_at` 超过 3 分钟的 Agent 返回 `offline`
  - 前端组件测试：无（UI 变更极小，手动验证即可）

- **提交信息**
  `fix: use last_seen_at freshness to determine agent online status`
