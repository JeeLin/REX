# 0.45.0: SQLite 连接器现代化

## Context

0.44.0 完成了 SQL 侧边栏存储过程/函数节点支持。MySQL 和 PostgreSQL 已通过统一的 `SqlConnector` trait 接入了完整的 REST API 层和新版 Navicat 风格侧边栏。

但 SQLite 使用了完全独立的 `SqliteConnector` trait（不继承 `SqlConnector`），导致：
- REST API 层完全拒绝 SQLite（`get_sql_connector()` 返回错误）
- 侧边栏无法通过 REST 端点获取 SQLite 的表/列信息
- 缺少 list_views、explain、DDL 等功能
- WebSocket handler 只支持 execute/tables/columns 3 个 action
- 前端新版 UI 无法与 SQLite 通信

本里程碑将 SQLite 从独立架构重构为统一架构，使其与其他 SQL 数据库享受相同的功能集。

版本类型：minor（重构 + 功能补齐，向后兼容）

## 产品边界

**做什么：**
- 重构 SQLite connector：实现 `SqlConnector` trait，替代独立的 `SqliteConnector`
- 接入 Hub REST API 层：`get_sql_connector()` 支持 SQLite
- 补齐缺失功能：list_views（通过 `sqlite_master WHERE type='view'`）、explain（`EXPLAIN QUERY PLAN`）
- WebSocket handler 升级：支持 databases/views/explain 等 action
- 前端适配：侧边栏智能过滤（SQLite 不显示存储过程/函数节点）

**不做什么：**
- 不修改产品文档
- 不重构 MySQL/PostgreSQL connector
- 不新增 UI 样式（沿用现有 Navicat 风格）
- 不实现全局查询对 SQLite 的支持（SQLite 无多库概念）

## 子任务详细设计

### 1 后端重构：SQLite 实现 SqlConnector trait

- **功能目标**：让 `SqliteConnectorImpl` 实现 `rex_common::sql::SqlConnector` trait，替代独立的 `SqliteConnector` trait
- **文件结构**：
  - 修改 `crates/rex-sqlite/src/connector.rs`（实现 SqlConnector trait）
  - 修改 `crates/rex-sqlite/src/lib.rs`（re-export 调整）
  - 修改 `crates/rex-sqlite/Cargo.toml`（添加 rex-common 依赖）
- **接口适配**：
  - `list_tables(database)` → SQLite 无 database 概念，忽略参数
  - `list_columns(database, table)` → 复用 `PRAGMA table_info`，转换为 `rex_common::sql::ColumnInfo`
  - `list_views(database)` → 新增：`SELECT name FROM sqlite_master WHERE type='view'`
  - `list_procedures(database)` → 使用 trait 默认实现（返回空 vec）
  - `explain(sql)` → 新增：`EXPLAIN QUERY PLAN <sql>`，解析为 `ExplainResult`
  - `execute(sql)` → 返回 `rex_common::sql::SqlResult`（替代 `SqliteResult`）
- **数据模型转换**：
  - `SqliteResult` (columns: `Vec<String>`) → `SqlResult` (columns: `Vec<SqlColumn>`)
  - `sqlite::ColumnInfo` (cid, notnull, default_value, pk) → `rex_common::sql::ColumnInfo` (name, data_type, is_nullable, is_primary_key)
- **测试标准**：`cargo test -p rex-sqlite` 通过
- **提交信息**：`feat: refactor SQLite connector to implement SqlConnector trait`

### 2 Hub API 集成：get_sql_connector 支持 SQLite

- **功能目标**：在 Hub REST API 层支持 SQLite，使所有 SQL 端点对 SQLite 可用
- **文件结构**：
  - 修改 `crates/rex-hub/src/sql.rs`（`get_sql_connector()` 添加 SQLite match arm）
  - 修改 `crates/rex-hub/src/sql.rs`（`get_ddl()` 添加 SQLite match arm）
  - 修改 `crates/rex-hub/src/sql.rs`（`create_connector()` 添加 SQLite 支持）
- **接口设计**：
  - `get_sql_connector()` 新增 `"sqlite"` match arm，从资源配置创建 `SqliteConnectorImpl`
  - `get_ddl()` 新增 SQLite DDL 获取（通过 `SELECT sql FROM sqlite_master WHERE name = ?`）
  - `create_connector()`（全局查询用）不添加 SQLite（SQLite 无多库概念）
- **DDL 实现**：
  - 表 DDL：`SELECT sql FROM sqlite_master WHERE type='table' AND name = '{table}'`
  - 视图 DDL：`SELECT sql FROM sqlite_master WHERE type='view' AND name = '{view}'`
- **测试标准**：`cargo test -p rex-hub` 通过
- **提交信息**：`feat: add SQLite support to Hub REST API endpoints`

### 3 WebSocket 升级：补齐缺失 action

- **功能目标**：让 ws_sqlite 支持 databases/views/explain 等缺失的 action
- **文件结构**：
  - 修改 `crates/rex-hub/src/ws_sqlite.rs`（添加新 action）
- **新增 action**：
  - `databases` → 返回当前 SQLite 文件路径作为唯一"数据库"（`[{ name: "main" }]`）
  - `views` → 调用 `list_views()` 返回视图列表
  - `explain` → 调用 `explain()` 返回执行计划
  - `columns` → 参数增加 `database`（忽略，保持向后兼容）
- **测试标准**：`cargo test -p rex-hub` 通过
- **提交信息** databases views：`feat: add databases and views actions to SQLite WebSocket handler`

### 4 前端适配：侧边栏智能过滤

- **功能目标**：SqlSidebar 根据协议类型智能过滤不支持的节点
- **文件结构**：
  - 修改 `packages/rex-console-web/src/features/sql/SqlSidebar.vue`
- **交互设计**：
  - 新增 prop：`protocol: string`（从 SqlConsole 传入）
  - 当 `protocol === 'sqlite'` 时：
    - 隐藏"存储过程/函数"区块（`showProcedures = false`）
    - 隐藏"视图"区块（SQLite 虽支持视图但侧边栏可选择性展示）
    - 隐藏数据库选择器（SQLite 无多库概念）
    - listTables 调用不传 database 参数（或传空值，后端忽略）
  - 当 `protocol === 'mysql'` 或 `'postgresql'` 时：保持现有行为
- **测试标准**：`bun run type-check && bun run lint` 通过
- **提交信息**：`feat: adapt SQL sidebar for SQLite protocol`
