# 0.70.4: SIP 资源按名称管理 + 多账户切换

## Context

M82a–M82d（0.70.0–0.70.3）打通了 SIP 电话全链路（信令/音频/视频/录音/抓包/CDR/质量监控）并完成整仓库质量收口（0.70.3）。至此 SIP 功能稳定。

但当前 SIP 资源管理按「账户」维度建模：一个 `sip` 资源 = 一份 `SipConfig`（`server`/`port`/`username`/`password`/`displayName`/`transport`），整体存于 `resources.config_json`。这与用户实际诉求不符——用户希望「按名称管理 SIP 身份、一个名称绑定一台 SIP 服务器、名称下挂多个账户并可切换当前生效账户」。

本阶段做**信令层资源/账户数据模型的结构性改造**（承接 /dev-bug 反馈），属 M82a 起即规划的演进路径，不在 0.70.1（明确「不改动信令层行为」）范围内。

版本类型：minor（数据模型迁移属向后兼容的渐进改造，无破坏性对外行为变更；`SipConfig` 作为「解析后生效配置」保持不变，仅拆分存储层与解析层）

## 产品边界

### 本阶段做什么
- **资源模型维度调整**：`sip` 资源从「账户」维度改为「名称 + server profile + 多账户」维度。
  - 名称（= `Resource.name`）= 一个 SIP 身份标签，绑定一台 SIP 服务器（注册域）。
  - server profile：`server`/`port`/`transport`（注册域）。
  - 多账户：名称下挂多个账户（`username`/`password`/`displayName`），可维护、可删除、可切换「当前生效账户」。
- **后端配置模型拆分**：`SipConfig`（既有，作为「解析后生效配置」保留不变）与新的 `SipProfile`（server profile + accounts[] + activeAccount）分离；`load_sip_conn` 解析 profile + 生效账户 → `SipConfig`。
- **数据迁移**：存量「账户」维度资源（旧 `config_json` 形状）平滑升级为「名称（单账户）」维度（启动期一次性迁移，幂等）。
- **前端改造**：资源创建/编辑向导先选名称 + 服务器，再维护多账户并切换生效账户；`features/sip/` 拨号面板适配多账户切换。
- **test-connection 与信令联调**适配新 schema（校验 `server` + 生效账户 `username`）。

### 本阶段不做什么
- 不改动 Hub/Agent 版本一致模型。
- 不改动媒体通道契约（PCM/视频帧 over WebSocket，M82b/M82c 已稳定）。
- 不改动 baresip FFI 边界（`SipUaTrait` 仍以单 `SipConfig` 注册/拨号——多账户切换在配置解析层完成，不触及 UA 实现）。
- 不引入多用户、RBAC、企业协作（CLAUDE.md 硬约束）。
- 不把文件传输数据经浏览器（与本次无关，重申不越界）。

## 新 SIP config_json 形状（存储层）

```json
{
  "server": "pbx.example.com",          // server profile：注册域
  "port": 5060,
  "transport": "udp",                    // udp / tcp / tls，默认 udp
  "accounts": [                          // 名称下挂载的多账户
    { "id": "a1", "username": "alice", "password": "secret", "displayName": "Alice" },
    { "id": "a2", "username": "bob",   "password": "secret2", "displayName": "Bob" }
  ],
  "activeAccount": "a1"                  // 当前生效账户 id
}
```

旧形状（迁移源）：`{ server, port, username, password, displayName, transport }`（单账户，无 accounts）。
迁移规则：包裹为 `accounts=[{ id, username, password, displayName }]`，`activeAccount = accounts[0].id`，`server`/`port`/`transport` 提升到顶层；`Resource.host`/`port` 仍同步为 server profile（与既有 `load_sip_conn` 回退逻辑一致），`Resource.username` 同步为生效账户 `username`（仅用于展示/兼容）。

`rex_sip::SipConfig`（既有）保持 `{ server, port, username, password, display_name, transport }`，作为「解析后生效配置」——Hub/Agent UA 仍按单 `SipConfig` 注册/拨号，多账户切换在解析层完成。

## 子任务详细设计

### 1 后端：SIP 配置模型拆分

- **功能目标**：在 `rex-common`/`rex-sip` 层定义 `SipAccount`、`SipProfile`；`SipConfig` 保持「解析后生效配置」语义不变；`load_sip_conn` 改为解析 `SipProfile` 并选取 `activeAccount` 构造 `SipConfig`。
- **文件结构**：
  - `crates/rex-sip/src/lib.rs`：新增 `SipAccount { id: String, username: String, password: Option<String>, display_name: Option<String> }`、`SipProfile { server: String, port: u16, transport: SipTransport, accounts: Vec<SipAccount>, active_account: String }`（均 `Serialize/Deserialize`，`#[derive(...)]` 与既有 `SipConfig` 一致）。
  - `crates/rex-hub/src/resource_conn.rs`：`load_sip_conn` 解析 `SipProfile`（旧的 `config_json` 单账户形状作为兼容分支保留：检测到无 `accounts` 字段则按旧逻辑构造临时 profile），取 `active_account` 对应账户，回退 `info.host`/`info.port`/`info.username` 的既有逻辑保持不变；输出 `SipConfig`。
- **接口设计**：纯内部解析函数，无新增 API 端点。`SipConfig` 线格式不变（Agent 隧道帧不受影响）。
- **后端流程**：`load_sip_conn(info)` → 解析 `info.config`（新/旧 shape）→ 取生效账户 → 组装 `SipConfig { server: profile.server, port, username: active.username, password: active.password, display_name: active.display_name, transport: profile.transport }`。
- **测试标准**：`resource_conn` 的 `#[cfg(test)]` 增补：(a) 新形状解析正确选出 activeAccount；(b) 旧形状兼容回退；(c) `info.host`/`port` 缺省回退到 profile；(d) activeAccount 不存在时回退到 `accounts[0]`。
- **提交信息**：`feat: split sip config into SipProfile + accounts, resolve active account in load_sip_conn (0.70.4 #1)`

### 2 后端：数据迁移

- **功能目标**：启动期对全部 `sip` 资源执行一次性幂等迁移——旧 `config_json` 形状（无 `accounts`）包裹为「名称（单账户）」新形状并 re-encrypt 写回。
- **文件结构**：
  - `crates/rex-hub/src/db.rs`：新增 `migrate_sip_resources(&self) -> Result<()>`。逻辑：遍历 `list_resources_by_protocol("sip")`；对每条解密 `config_json`；若 `accounts` 字段缺失（旧形状）→ 构造 `SipProfile`，`accounts=[{id, username, password, displayName}]`，`activeAccount=accounts[0].id`；re-encrypt 后 `update_resource_config`；跳过已是新形状的资源（幂等）。
  - `crates/rex-hub/src/main.rs`（或 app 启动处）：在现有 `migrations.sql` 应用之后调用 `db.migrate_sip_resources()`。
- **接口设计**：无新增 API。迁移失败应记录 `tracing::error!` 且**不阻断启动**（仅该资源保持旧形状，待下一次启动重试）。
- **后端流程**：启动 → `apply_migrations` → `migrate_sip_resources`（遍历→解密→判形状→包裹→re-encrypt→写回）。
- **测试标准**：`db.rs` 测试（`rex-hub` 测试 DB）：构造旧形状 sip 资源 → `migrate_sip_resources` → 读回为新形状（含 `accounts` 且 `activeAccount` 指向唯一账户）；对新形状资源再次调用应为幂等（无变化/不报错）。
- **提交信息**：`feat: migrate legacy single-account sip resources to name+multi-account shape (0.70.4 #2)`

### 3 后端：test-connection + 信令联调适配

- **功能目标**：`test_connection` 的 `sip` 分支与新 schema 对齐；`sip_ws.rs` 注册/拨号走解析后的 `SipConfig`（已通过 #1 的 `load_sip_conn` 实现，此处补校验与联调）。
- **文件结构**：
  - `crates/rex-hub/src/resource_api.rs`：`test_connection` 的 `sip` 分支改为：解析 `config_json` 为 `SipProfile`，取 activeAccount 的 `username`；校验 `server`（回退 `body.host`）+ 生效账户 `username` 非空。
  - `crates/rex-hub/src/sip_ws.rs`：确认 `cfg: &SipConfig` 来自 `load_sip_conn`（新模型自动生效）；既有注册/拨号逻辑不变，补一处断言确保 activeAccount 生效。
- **接口设计**：`POST /api/environments/{env_id}/test-connection` 行为不变，仅校验逻辑适配。
- **后端流程**：test-connection sip → 解析 profile → 选 activeAccount → 校验 server+username。
- **测试标准**：`resource_api` 的 sip test-connection：(a) 新形状 + 生效账户 → ok；(b) 缺 server → 失败；(c) 缺 activeAccount 的 username → 失败。
- **提交信息**：`fix: align sip test-connection validation with name+multi-account model (0.70.4 #3)`

### 4 前端：SIP 资源创建/编辑向导

- **功能目标**：`sip` 协议的资源创建/编辑表单改为「名称（资源名）+ server profile + 多账户（增删/设生效）」。
- **文件结构**：
  - `packages/rex-console-web/src/features/resource/` 与 `features/resource-panel/`：sip 协议分支的表单组件新增 `server`/`port`/`transport` 输入 + 账户列表（add/remove/set-active）。
  - `packages/rex-console-web/src/features/workspace/ResourceProperties.vue`：sip 资源属性编辑适配新模型。
  - `packages/rex-console-web/src/api/resources.ts`：构造/解析 sip `config_json` 为 `SipProfile` 形状（与后端一致）。
- **接口设计**：提交 `NewResource`（`config_json` 为 `SipProfile` JSON，与后端 schema 对齐）。
- **前端交互设计**：向导顺序——名称 → 服务器（host/port/transport）→ 账户列表（至少 1 个，可增删，单选「生效」）。删除生效账户时自动改选首个。
- **测试标准**：`features/resource/__tests__/` 或对应 `__tests__` 新增：账户新增/删除/设生效写入 `config_json` 正确；至少 1 个账户校验；`ResourceProperties.vue` 加载新形状正确回填。
- **提交信息**：`feat: sip resource create/edit wizard with name + server profile + multi-account (0.70.4 #4)`

### 5 前端：`features/sip/` 拨号面板多账户切换

- **功能目标**：`SipPage`/`Dialpad` 适配「名称 + 多账户」——展示生效账户，提供切换当前生效账户的下拉/控件（切换即更新资源 `activeAccount` 并写回）。
- **文件结构**：
  - `packages/rex-console-web/src/features/sip/SipPage.vue`：账户切换控件 + 生效账户显示。
  - `packages/rex-console-web/src/features/sip/Dialpad.vue`：拨号使用生效账户（已隐含于资源配置）。
  - `packages/rex-console-web/src/api/resources.ts`：新增 `setActiveSipAccount(resourceId, accountId)`（复用 `update_resource` 端点，更新 activeAccount 后写回）。
  - `__tests__/`：账户切换调用 activeAccount 更新。
- **接口设计**：切换生效账户 = `PUT /api/environments/{env_id}/resources/{resource_id}`（仅 `config_json.activeAccount` 变更），复用既有更新端点。
- **前端交互设计**：切换生效账户后应提示「下次 REGISTER 使用新账户」（不强制实时 re-register；当前通话不受影响）。
- **测试标准**：`SipPage.test.ts` / `Dialpad.test.ts` 增补：切换账户触发 activeAccount 写回；生效账户显示正确。
- **提交信息**：`feat: sip panel multi-account switch UI (0.70.4 #5)`
