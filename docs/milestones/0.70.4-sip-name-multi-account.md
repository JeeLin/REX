# 0.70.4: SIP 资源按名称管理 + 多账户切换

## Context

M82a–M82d（0.70.0–0.70.3）打通了 SIP 电话全链路（信令/音频/视频/录音/抓包/CDR/质量监控）并完成整仓库质量收口（0.70.3）。至此 SIP 功能稳定。

但当前 SIP 资源管理按「账户」维度建模：一个 `sip` 资源 = 一份 `SipConfig`（`server`/`port`/`username`/`password`/`displayName`/`transport`），整体存于 `resources.config_json`。这与用户实际诉求不符——用户希望「按名称管理 SIP 身份、一个名称绑定一台 SIP 服务器、名称下挂多个账户并可切换当前生效账户」。

本阶段做**信令层资源/账户数据模型的结构性改造**（承接 /dev-bug 反馈），属 M82a 起即规划的演进路径，不在 0.70.1（明确「不改动信令层行为」）范围内。

版本类型：minor（数据模型迁移属向后兼容的渐进改造，无破坏性对外行为变更；`SipConfig` 作为「解析后生效配置」保持不变，仅拆分存储层与解析层）

## 产品边界

### 本阶段做什么
- **资源模型维度调整**：`sip` 资源从「账户」维度改为「名称（仅展示分组）+ 多账户」维度，每个账户自带完整 server profile。
  - 名称（= `Resource.name`）= 展示分组标签，不绑定服务器，不进 `config_json`。
  - 多账户：名称下挂多个账户，每个账户自带 `server`/`port`/`transport` + `username`/`password`/`displayName`，可维护、可删除、可切换「当前生效账户」。
- **后端配置模型拆分**：`SipConfig`（既有，作为「解析后生效配置」保留不变）与新的 `SipProfile`（accounts[] + activeAccount）分离；`load_sip_conn` 解析 profile + 选出生效账户 → 取该账户 server/port/transport/凭据构造 `SipConfig`。
- **前端改造**：资源创建/编辑向导选名称后维护多账户（每账户自带 server/port/transport）并切换生效账户；`features/sip/` 拨号面板适配多账户切换。
- **test-connection 与信令联调**适配新 schema（校验生效账户 server + username）。

### 本阶段不做什么
- 不改动 Hub/Agent 版本一致模型。
- 不改动媒体通道契约（PCM/视频帧 over WebSocket，M82b/M82c 已稳定）。
- 不改动 baresip FFI 边界（`SipUaTrait` 仍以单 `SipConfig` 注册/拨号——多账户切换在配置解析层完成，不触及 UA 实现）。
- 不引入多用户、RBAC、企业协作（CLAUDE.md 硬约束）。
- 不把文件传输数据经浏览器（与本次无关，重申不越界）。

## 新 SIP config_json 形状（存储层）

```json
{
  "accounts": [                          // 名称下挂载的多个账户，每个账户自带完整 server profile + 凭据
    {
      "id": "a1", "server": "pbx.example.com", "port": 5060, "transport": "udp",
      "username": "alice", "password": "secret", "displayName": "Alice"
    },
    {
      "id": "a2", "server": "pbx2.example.com", "port": 5061, "transport": "tls",
      "username": "bob", "password": "secret2", "displayName": "Bob"
    }
  ],
  "activeAccount": "a1"                  // 当前生效账户 id
}
```

- **名称只做展示分组**：资源的「名称」取 `Resource.name`，不进 `config_json`；`config_json` 仅含 `accounts[]` + `activeAccount`。
- **每个账户自带完整 server profile**：`server` / `port` / `transport` 与登录凭据 `username` / `password` / `displayName` 都在账户对象内。同一名称下不同账户可指向不同 SIP 服务器/传输方式。
- 字段默认值：`port` 缺省 5060，`transport` 缺省 udp。

`rex_sip::SipConfig`（既有）保持 `{ server, port, username, password, display_name, transport }`，作为「解析后生效配置」——`load_sip_conn` 选出生效账户后，直接取该账户的 server/port/transport/凭据构造 `SipConfig`；Hub/Agent UA 仍按单 `SipConfig` 注册/拨号，多账户切换在解析层完成，不触及 FFI/隧道帧。

> 注：本版本**不做数据迁移**（用户明确），仅支持新形状；旧形状资源需由用户重新创建。

## 子任务详细设计

### 1 后端：SIP 配置模型拆分

- **功能目标**：在 `rex-sip` 层定义 `SipAccount`（自带 `server`/`port`/`transport` + 凭据）、`SipProfile`（`accounts[]` + `active_account`）；`SipConfig` 保持「解析后生效配置」语义不变；`load_sip_conn` 解析 `SipProfile` 并选取生效账户、直接取该账户 server/port/transport/凭据构造 `SipConfig`。**不做旧形状兼容**。
- **文件结构**：
  - `crates/rex-sip/src/lib.rs`：`SipAccount { id, server, port, transport, username, password, display_name }`、`SipProfile { accounts: Vec<SipAccount>, active_account: String }`（均 `Serialize/Deserialize`）。
  - `crates/rex-hub/src/resource_conn.rs`：`load_sip_conn` 解析 `SipProfile`，选 `active_account` 对应账户（缺省回退 `accounts[0]`），账户 `server` 缺省时回退 `info.host`，账户 `port` 缺省时回退 `info.port`/5060；组装 `SipConfig`。移除旧形状兼容分支。
- **接口设计**：纯内部解析函数，无新增 API 端点。`SipConfig` 线格式不变（Agent 隧道帧不受影响）。
- **后端流程**：`load_sip_conn(info)` → 解析 `info.config`（SipProfile）→ 选出生效账户 → 取该账户 server/port/transport/凭据 → `SipConfig`。
- **测试标准**：`resource_conn` 的 `#[cfg(test)]` 增补：(a) 新形状解析正确选出 activeAccount 且 server/port/transport 取自身值；(b) activeAccount 不存在回退 `accounts[0]`；(c) 账户 `server` 缺省回退 `info.host`；(d) 无账户/无 username 报错。
- **提交信息**：`feat: split sip config into SipProfile + accounts, account carries server profile (0.70.4 #1)`

### 2 后端：test-connection + 信令联调适配

- **功能目标**：`test_connection` 的 `sip` 分支与新 schema 对齐（校验生效账户 server + username）；`sip_ws.rs` 注册/拨号走解析后的 `SipConfig`（已通过 #1 的 `load_sip_conn` 实现，无需迁移/兼容）。
- **文件结构**：
  - `crates/rex-hub/src/resource_api.rs`：`test_connection` 的 `sip` 分支改为解析 `config_json` 为 `SipProfile`，取 activeAccount 对应账户的 `server`（回退 `body.host`）+ `username` 校验非空。
  - `crates/rex-hub/src/sip_ws.rs`：确认 `cfg: &SipConfig` 来自 `load_sip_conn`（新模型自动生效）；既有注册/拨号逻辑不变。
- **接口设计**：`POST /api/environments/{env_id}/test-connection` 行为不变，仅校验逻辑适配。
- **后端流程**：test-connection sip → 解析 profile → 选 activeAccount → 校验 server+username。
- **测试标准**：`resource_conn`/`resource_api` 的 sip 校验：(a) 新形状 + 生效账户 → ok；(b) 缺 server → 失败；(c) 缺 activeAccount 的 username → 失败。
- **提交信息**：`fix: align sip test-connection validation with name+multi-account model (0.70.4 #2)`

### 3 前端：SIP 资源创建/编辑向导

- **功能目标**：`sip` 协议的资源创建/编辑表单改为「名称（资源名）+ 多账户（每账户自带 server/port/transport，增删/设生效）」。
- **文件结构**：
  - `packages/rex-console-web/src/features/resource/WizardModal.vue`：sip 协议分支表单改造为多账户编辑，每账户含 server/port/transport/username/password/displayName。
  - `packages/rex-console-web/src/features/workspace/ResourceProperties.vue`：sip 资源属性编辑适配新模型。
- **接口设计**：提交 `NewResource`（`config_json` 为 `SipProfile` JSON，与后端 schema 对齐）。
- **前端交互设计**：向导顺序——名称 → 账户列表（至少 1 个，每账户自带 server/port/transport，可增删，单选「生效」）。删除生效账户时自动改选首个。
- **测试标准**：`features/resource/__tests__/` 新增：账户新增/删除/设生效写入 `config_json` 正确（server/port/transport 在账户内）；至少 1 个账户校验；`ResourceProperties.vue` 加载新形状正确回填。
- **提交信息**：`feat: sip resource create/edit wizard with name + per-account server profile + multi-account (0.70.4 #3)`

### 4 前端：`features/sip/` 拨号面板多账户切换

- **功能目标**：`SipPage` 适配「名称 + 多账户」——展示生效账户，提供切换当前生效账户的下拉/控件（切换即更新资源 `activeAccount` 并写回）。
- **文件结构**：
  - `packages/rex-console-web/src/features/sip/SipPage.vue`：账户切换控件 + 生效账户显示（解析 `config_json` 的 `accounts`/`activeAccount`）。
  - `packages/rex-console-web/src/api/resources.ts`：切换生效账户复用 `update_resource` 端点（更新 activeAccount 后写回）。
  - `__tests__/`：账户切换调用 activeAccount 更新。
- **接口设计**：切换生效账户 = `PUT /api/environments/{env_id}/resources/{resource_id}`（仅 `config_json.activeAccount` 变更），复用既有更新端点。
- **前端交互设计**：切换生效账户后下次 REGISTER 使用新账户（不强制实时 re-register；当前通话不受影响）。
- **测试标准**：`SipPage.test.ts` 增补：切换账户触发 activeAccount 写回；生效账户显示正确。
- **提交信息**：`feat: sip panel multi-account switch UI (0.70.4 #4)`
