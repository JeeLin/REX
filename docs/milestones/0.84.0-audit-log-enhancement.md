# 0.84.0: 审计日志增强

## Context
0.83.1 修复了工作空间交互可靠性（分屏拖拽、快捷键、终端复制粘贴）。当前审计日志存在两个核心问题（AGENTS.md #10、#11）：
- 审计日志操作值显示英文而非中文（部分操作类型在 DB 中存为英文 key，前端 i18n 已覆盖但 detail_json 字段中的原始 key 未翻译）
- 审计日志详情无实际价值（detail_json 常为空或仅含少量信息）

更关键的是，审计日志仅覆盖 REST API 层操作（环境/资源 CRUD、登录），WebSocket 层的连接操作（SSH 连接/断开、SQL 查询、文件传输等）完全没有记录。本阶段将审计日志从"管理操作记录"提升为"完整操作审计"。

版本类型：minor（新增审计能力，向后兼容）

## 产品边界
本阶段做什么：
- 丰富已有 REST API 操作的 detail_json（结构化上下文信息）
- 新增 WebSocket 层操作审计（SSH/SQL/SFTP/Redis 连接与操作）
- 前端审计详情展示优化（格式化 detail、中文标签、复制功能）
- 补充审计日志单元测试

本阶段不做什么：
- 不修改审计日志数据模型（audit_log 表结构不变）
- 不新增审计日志 API 端点
- 不涉及 Agent 端审计（Agent 无数据库写入能力）
- 不涉及新功能开发

## 子任务详细设计

### 1 审计日志详情丰富化

- **功能目标**：为已有 REST API 层审计日志写入点补充结构化 detail_json，同时解析 environment_id/resource_id 为可读名称存入 summary 或 detail。
- **文件结构**（修改）：
  - `crates/rex-hub/src/audit.rs`：新增 `AuditDetail` 结构体（各操作类型的 detail 字段统一为 `serde_json::Value`）；`write_audit_log` 签名新增 `env_name: Option<&str>`、`resource_name: Option<&str>` 参数（可选，用于 summary 拼接）
  - `crates/rex-hub/src/auth.rs`（`write_audit_log` 调用处 ~:54, :87, :131）：补充 detail（login_failure: `{"ip","reason","attempts"}`; login_success: `{"ip","user_agent","session_timeout"}`）
  - `crates/rex-hub/src/env.rs`（~:165, :280, :355）：补充 detail（`{"env_name","old_name"(update), "description"}`），summary 改为 `"创建环境 {name}"`
  - `crates/rex-hub/src/resource.rs`（~:136, :231, :281, :599）：补充 detail（`{"resource_name","protocol","host","port","connection_type"}`），summary 改为 `"创建资源 {name}"`
- **接口设计**：
  - `write_audit_log` 新签名：增加 `env_name: Option<&str>`, `resource_name: Option<&str>` 参数，均向后兼容（None 时保持原行为）
  - detail 参数类型从 `Option<&str>` 改为 `Option<&serde_json::Value>`（内部 `.to_string()` 后存入 DB）
- **交互设计**：无前端交互变更，仅数据层变更
- **后端流程**：
  1. 在 REST handler 中，执行操作前查询环境/资源名称
  2. 构造 `serde_json::json!({...})` detail
  3. 调用 `write_audit_log` 传入 detail 和名称
- **测试标准**：
  - `write_audit_log` 现有测试通过（签名变更后适配）
  - 新增测试：验证 detail_json 内容正确写入并可读取
  - 新增测试：验证 env_name/resource_name 参与 summary 拼接
- **提交信息**：`feat(audit): enrich detail_json and resolve env/resource names`

### 2 WebSocket 层操作审计

- **功能目标**：在 WebSocket 连接建立/断开和关键操作执行时写入审计日志，覆盖 SSH、SQL（MySQL/PostgreSQL/SQLite）、SFTP、Redis 六种协议。
- **文件结构**（修改）：
  - `crates/rex-hub/src/ws_terminal.rs`：在 `handle_terminal_socket` 入口（连接建立）和 `socket.closed()`（连接断开）处调用 `write_audit_log`
  - `crates/rex-hub/src/ws_mysql.rs`：在 `handle_mysql_socket` 连接/断开处写入审计
  - `crates/rex-hub/src/ws_postgresql.rs`：在 `handle_pg_socket` 连接/断开处写入审计
  - `crates/rex-hub/src/ws_sqlite.rs`：在 `handle_sqlite_socket` 连接/断开处写入审计
  - `crates/rex-hub/src/ws_redis.rs`：在 `handle_redis_socket` 连接/断开处写入审计
  - `crates/rex-hub/src/transfer.rs`（`create_transfer` ~:72-103）：在传输任务创建时写入审计
- **接口设计**：
  - 审计操作类型：`connect`（连接建立）、`disconnect`（连接断开）、`query`（SQL 查询执行）、`upload`/`download`（文件传输）
  - detail 格式：`{"resource_name","protocol","host","port","session_duration_ms"(disconnect时),"query_count"(disconnect时)}`
  - summary 格式：`"SSH 连接 {resource_name}"` / `"SSH 断开 {resource_name}（持续 5m30s）"`
- **交互设计**：无前端交互变更
- **后端流程**：
  1. WebSocket handler 入口处，从 DB 查询资源配置（resource_name, host, port, protocol）
  2. 连接建立时：`write_audit_log(db, "connect", "success", summary, env_id, res_id, agent_id, detail, ip)`
  3. 连接断开时：计算会话时长，`write_audit_log(db, "disconnect", "success", summary, ...)`
  4. SQL query 操作：在 ws_common 的 query action handler 中，每 N 次查询或连接断开时记录 query 计数
  5. 文件传输：在 transfer create 时记录 upload/download
- **测试标准**：
  - 新增测试：模拟 WebSocket handler 入口调用，验证 `connect`/`disconnect` 审计记录写入
  - 新增测试：验证 disconnect 记录包含 session_duration_ms
  - 新增测试：验证 transfer create 写入 upload 审计记录
- **提交信息**：`feat(audit): add WebSocket layer operation audit logging`

### 3 前端审计详情展示优化

- **功能目标**：将展开详情从原始 key-value 改为格式化的信息网格，中文标签，支持复制单个字段值。
- **文件结构**（修改）：
  - `packages/rex-console-web/src/pages/AuditLog.vue`（~:115-131，详情展开区域）
  - `packages/rex-console-web/src/i18n/zh.ts`（audit.detail 扩展）
  - `packages/rex-console-web/src/i18n/en.ts`（audit.detail 扩展）
- **接口设计**：无 API 变更
- **交互设计**：
  - 详情网格：每行显示 `中文标签 : 值`，标签从 i18n `audit.detail.{key}` 获取
  - 复制按钮：每个值右侧显示小复制图标，点击复制该值到剪贴板
  - 协议/操作类型：用彩色徽章展示（复用现有 protocol badge 样式）
  - 会话时长：格式化为 `Xm Ys`（从毫秒转换）
- **后端流程**：无
- **测试标准**：
  - 前端单元测试：mock 审计记录含 detail JSON，断言展开后显示中文标签
  - 前端单元测试：断言复制按钮点击后调用 `navigator.clipboard.writeText`
- **提交信息**：`feat(audit): format detail grid with Chinese labels and copy support`

## 设计核对点

- **产品文档一致性**：审计日志 §3.10 定义的操作类型颜色编码（SSH 连接=绿色、SQL 查询=蓝色、文件上传=紫色等）在前端展示中保持一致
- **数据模型兼容**：audit_log 表结构不变，仅 detail_json 内容更丰富；不引入新表或新列
- **向后兼容**：`write_audit_log` 签名新增参数带默认值（Option），现有调用点无需全部立即迁移
- **审计覆盖范围**：REST API 层（环境/资源 CRUD、登录）+ WebSocket 层（SSH/SQL/SFTP/Redis 连接/断开）= 完整操作审计
- **detail_json 规范**：统一使用 `serde_json::Value` 构造，key 使用 snake_case，前端通过 i18n key `audit.detail.{key}` 映射中文标签
- **性能影响**：审计写入是同步阻塞（当前 `let _ = conn.execute(...)` 模式），WebSocket 断开时写入不影响连接清理流程
