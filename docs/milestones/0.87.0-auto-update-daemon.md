# 0.87.0: 自动更新可靠性与部署守护

## Context

0.86.0 完成了文件传输并发控制与 Redis/SQL 界面完善。0.21.0 已打通 Agent 自动更新的核心链路（Hub 心跳下发 `needs_update` → Agent 下载 → SHA256 校验 → 备份 → `exit 10` → supervisor 二进制替换/回滚/健康检查），0.6.0–0.7.0 已完成 Hub 侧更新基础设施。

但经代码核查，当前实现存在两个层面的真实缺口：

1. **部署守护缺口（关键）**：`rex-hub`/`rex-agent` 的 supervisor 模式（含 `run_update_supervisor`，负责捕获 `exit 10` 做二进制替换与崩溃重启）只在「非 `--worker`」分支启动。而 `Dockerfile.hub` 的 `CMD ["/app/rex-hub", "--worker"]` 与 Agent compose 均直接以 `--worker` 模式运行，supervisor 永不启动。后果：Docker/进程部署下，Agent 的「跟随 Hub 自动更新并自重启」实际不生效，`exit 10` 与进程崩溃均不会被 in-container supervisor 捕获。
2. **可靠性与可观测性缺口**：自动更新过程在前端无进度/状态呈现（UpdateSection 仅显示手动 Hub 更新与 Agent 版本列表）；下载失败、WS 重连中断时 `perform_update` 静默返回，无重试/回滚用户提示；Agent 可能通过 GitHub 兜底拉取到未随当前 Hub 部署的版本。

本里程碑聚焦：**让 Hub/Agent 在 Docker 与 systemd 部署下以 supervisor 模式运行（崩溃自拉起、升级自替换），并补齐 Agent 自动更新的可靠性与前端状态呈现**。Hub 自身更新保持用户手动 `check/download/apply` 流程不变。

版本类型：minor（新增部署模式 + 可靠性增强 + 前端状态，向后兼容），版本号 0.87.0。

## 产品边界

**做什么：**
- 部署层：Docker Hub/Agent 镜像与 compose 改为 supervisor 模式；新增 systemd unit 模板（Hub/Agent）
- Agent 自动更新可靠性：下载/校验失败重试与退避、WS 重连期间更新状态保持、避免拉取未部署版本
- 前端：Agent 自动更新进度/状态呈现（更新中/已回滚/版本不一致）、`auto_update` 开关状态展示
- CI：确保 Agent 二进制随 Hub 镜像打包到 `agent-binaries/`，使内网无外网时仍可分发

**不做什么：**
- 不改动 Hub 自身的手动更新流程（check/download/apply 不变）
- 不实现 Agent 配置热推送（已在 0.21.0 范围外）
- 不做全站 UI 重新设计（用户已明确留作下一轮计划）
- 不涉及多用户/RBAC/企业协作（AGENTS.md 硬性约束）

## 子任务详细设计

### 1 部署守护：Docker/compose 与 systemd 改为 supervisor 模式

- **功能目标**：让 `exit 10`（更新请求）与进程崩溃在容器内/系统服务内被 supervisor 捕获，实现自动重启与二进制替换。
- **文件结构**：
  - 修改：`Dockerfile.hub`（CMD 去掉 `--worker`，由 supervisor 派生 worker）
  - 修改：`Dockerfile.agent`（若存在；当前 Agent 镜像由 CI 构建，需确认并统一 CMD）
  - 修改：`docker-compose.hub.yaml` / `docker-compose.agent.yaml`（保持 `restart: unless-stopped` 作为容器级兜底，新增健康检查 `healthcheck`）
  - 新增：`deploy/rex-hub.service`（systemd unit 模板，ExecStart 为 supervisor 模式）
  - 新增：`deploy/rex-agent.service`（systemd unit 模板）
  - 修改：`crates/rex-common/src/app.rs`（确保 supervisor 模式默认入口在无 `--worker` 时正确派生 worker 并传递 `data_dir`）
- **接口设计**：无新 API。行为变更：容器/服务以 supervisor 模式启动，`run_update_supervisor_from_args` 作为 PID 1，派生 `rex-hub --worker` 子进程。
- **交互设计**：部署方式不变（`docker compose up -d` / `systemctl start rex-hub`）；用户无感知切换。
- **后端流程**：supervisor 捕获 `exit 10` → `perform_replacement`（staged→当前）→ 启动新 worker 并注入 `REX_UPDATE_PENDING` → 新 worker 健康检查（register 成功 `exit 0` / 失败 `exit 11`）→ `Committed` 或 `rollback`；崩溃（非 0）按 `MAX_ATTEMPTS` 重启或回滚。
- **测试标准**：
  - `cargo test -p rex-common` 现有 supervisor 测试通过（含 `exit 10` → 替换 → 提交/回滚路径）
  - 文档确认 Docker CMD 变更且 `cargo build --release` 产物以 supervisor 模式可启动
- **提交信息**：`chore: run hub/agent in supervisor mode (Docker/compose/systemd)`

### 2 Agent 自动更新可靠性加固

- **功能目标**：Agent 自动更新在下载失败、校验失败、WS 重连等异常下具备重试与回滚能力，且不拉取未随 Hub 部署的版本。
- **文件结构**：
  - 修改：`crates/rex-agent/src/ws.rs`（`perform_update`：下载失败重试+退避、`sha256` 缺失时拒绝；`needs_update` 与 `hub_version` 一致性校验）
  - 修改：`crates/rex-hub/src/agent_download.rs`（版本门禁：仅当请求版本与 `REX_AGENT_VERSION`/本地打包版本匹配时才下发，否则 409/404；避免 GitHub 兜底拉取任意版本）
  - 修改：`crates/rex-common/src/update_state.rs`（如需要记录 `rollback_reason` 便于前端展示）
- **接口设计**：`GET /api/agent/download?os=&arch=&version=` 新增可选 `version` 参数；不匹配时返回 `VERSION_MISMATCH`。
- **后端流程**：心跳 `needs_update` → `perform_update(hub_version)` → 下载（重试 3 次，指数退避）→ SHA256 校验（缺失则中止）→ 版本门禁校验 → 备份 → 写 `update-state.json(Requested)` → `exit 10`；supervisor 完成替换/回滚。
- **测试标准**：
  - `cargo test -p rex-agent` 新增：`perform_update` 下载失败重试后成功、SHA256 不匹配中止、版本门禁拒绝
  - `cargo test -p rex-hub` 新增：`download_agent` 版本不匹配返回错误
- **提交信息**：`fix: agent auto-update retry/rollback and version gating`

### 3 前端 Agent 更新状态与 auto_update 展示

- **功能目标**：在设置页版本总览中呈现 Agent 自动更新的实时状态，让用户感知更新进度与结果。
- **文件结构**：
  - 修改：`packages/rex-console-web/src/api/update.ts`（`AgentVersionInfo` 新增可选字段 `update_phase`、`update_error`、`auto_update`）
  - 修改：`packages/rex-console-web/src/features/settings/UpdateSection.vue`（Agent 版本行展示：更新中/已回滚/版本不一致；`auto_update` 开关状态徽章）
  - 修改：`packages/rex-console-web/src/api/agent.ts`（Agent config 已含 `auto_update`，补充状态读取）
  - 修改：`packages/rex-console-web/src/i18n/{en,zh}.ts`（新增 `settings.update.agentUpdating`、`agentRolledBack`、`agentVersionMismatch`、`autoUpdateOn/Off` 等）
- **接口设计**：复用 `GET /api/update/agents`；`AgentVersionInfo` 新增 `update_phase: 'idle'|'downloading'|'replacing'|'rolled_back'|'mismatch' | null`。
- **交互设计**：Agent 版本列表中，在线且 `needs_update` 时显示「更新中」动画；`rolled_back` 显示红色「已回滚」；`mismatch` 显示「版本不一致，请同步 Hub」提示；`auto_update` 关闭时显示灰色开关徽章。
- **测试标准**：`bun run type-check` / `lint` / `build` 通过；无需新增单测（交互组件，遵循项目惯例）。
- **提交信息**：`feat: surface agent auto-update status and auto_update toggle in UI`

### 4 CI：Agent 二进制随 Hub 镜像打包

- **功能目标**：确保 CI 构建的 Agent 二进制随 Hub 镜像进入 `agent-binaries/`，使内网无外网环境 Agent 仍可从 Hub 拉取更新。
- **文件结构**：
  - 修改：`.github/workflows/ci.yml`（build-hub 阶段后追加 build-agent，将产物拷贝到 `dist/agents/<arch>/rex-agent`）
  - 修改：`scripts/build-hub-image.sh`（本地构建脚本同步追加 agent 构建步骤，便于离线验证）
  - 确认：`Dockerfile.hub` 已 `COPY dist/agents/ /app/data/agent-binaries/`（当前存在，需确认布局匹配 `agent_download.rs` 的 flat/nested 查找）
- **后端流程**：CI 产出 `dist/agents/{arch}/rex-agent` → Dockerfile COPY 到 `/app/data/agent-binaries/` → `download_agent` 优先本地命中，避免 GitHub 兜底。
- **测试标准**：CI 构建产物含 `agent-binaries/`；本地 `build-hub-image.sh` 执行后镜像内 `/app/data/agent-binaries/` 有对应二进制。
- **提交信息**：`ci: bundle agent binaries into hub image`

## 设计核对点

依据 `AGENTS.md` 与产品文档，本阶段关键检查项：
- **部署模式正确性**：Docker/compose/systemd 必须以 supervisor 模式运行，`exit 10` 与崩溃能被捕获（Hub 仅支持 Docker 部署，但 systemd 模板作为可选自托管方式补充）
- **版本一致性**：Agent 仅能更新到随当前 Hub 部署的版本，禁止 GitHub 兜底拉取任意版本
- **回滚可靠性**：`MAX_ATTEMPTS` 超限后自动回滚到旧版本并设 `RolledBack` 状态
- **前端状态可见性**：更新中/已回滚/版本不一致在设置页可感知，不静默失败
- **单用户约束**：不引入多用户/RBAC
- **向后兼容**：API 仅新增可选字段，不破坏既有前端
