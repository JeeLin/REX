# M19 步骤2：设计核对报告

## 审查维度

### 产品一致性

- [x] **SFTP 抽屉符合 PRODUCT 3.6** — 产品文档明确说"内置 SFTP 抽屉：工具栏「SFTP」按钮，在右侧/下方打开内嵌文件面板"。M19 设计将其放在状态栏 + Ctrl+B 快捷键，一致。
- [x] **符合 PRODUCT 3.8 文件管理定位** — 产品描述的双面板本地/远程是 Xftp 完整模式。M19 作为 SSH 内嵌抽屉，聚焦远程文件浏览是合理的渐进实现。
- [x] **传输队列符合 PRODUCT 3.8** — "底部常驻可折叠抽屉"、进度/速率/暂停/恢复/取消，均在设计中。
- [x] **单用户** — 无多用户、RBAC。
- [x] **自托管** — 无云服务依赖。
- [x] **S3 保持独立** — S3 与 SSH 无关，保持独立 Tab，符合产品逻辑。

### 架构一致性

- [x] **不引入新后端 API** — SFTP 抽屉复用现有 `/api/files/*` 端点，后端无需改动。
- [x] **SSH 连接方式一致** — 抽屉使用 Tab 的 resourceId + credentials 连接，与 TerminalView 一致。
- [x] **后端独立会话** — 当前 SFTP 抽屉在后端创建独立 HTTP 会话（非复用 SSH 连接），这是已知的架构限制，文档中已标注"后续优化"。

### 概念污染检查

- [x] 无多用户概念引入
- [x] 无 RBAC 概念引入
- [x] 无企业协作概念引入
- [x] 无外部 SaaS 依赖

### 子任务拆分

- [x] 两个子任务粒度合理（每个 1 commit）

### 发现的问题

**🟡 小问题**（无需打回，直接修正）：

1. **PRODUCT 2.3 仍列出 SFTP 为独立协议**：产品文档的协议表中 SFTP 仍作为独立类型。需要更新产品文档，说明 SFTP 通过 SSH Tab 抽屉访问，不再作为独立资源类型。但这属于产品文档同步，不影响 M19 设计方向。

2. **本地/远程双面板未包含**：PRODUCT 3.8 描述的"左面板 — 本地文件浏览；右面板 — 远程文件浏览"在 M19 中未实现。当前 FilesPage 两个面板都是远程目录。这是合理的范围控制——M19 聚焦 SSH 集成，完整双面板可作为后续里程碑。

## 结论

**✅ 通过**

M19 设计与产品文档高度一致。PRODUCT 3.6 明确要求 SSH 内置 SFTP 抽屉，M19 的实现方案（底部可折叠抽屉 + 快捷键 + 自动连接）完全符合。两个小问题不阻塞开发，可在后续迭代中处理。
