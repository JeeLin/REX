# 0.86.0 文件传输并发控制与界面完善

## 概述

本次里程碑聚焦文件传输并发数量控制功能，以及 Redis/SQL 已有功能的体验优化。经过 0.79.0 和 0.81.0 两个里程碑的开发，Redis 和 SQL 控制台的核心功能已基本实现。本次主要补充并发控制的用户可配置能力，并完善细节体验。

## 子任务

### 子任务 1：文件传输并发数量控制

**目标**：让用户可以在前端配置同时传输的最大任务数，而非使用硬编码的默认值 3。

**技术方案**：
- 后端：在 `TransferManager` 中新增 `set_max_concurrent` 方法，动态调整 `Semaphore` 的许可数
- 后端：新增 API `PUT /api/transfer/concurrency` 接受 `{ max_concurrent: usize }` 参数
- 后端：新增 API `GET /api/transfer/concurrency` 返回当前配置
- 前端：在设置页面新增 "传输" 配置区域，包含并发数滑块/输入框（范围 1-10）
- 前端：`TransferQueuePanel` 中将 `max_concurrent` 改为从 API 获取的可配置值

**验收标准**：
- 用户可以在设置页面修改传输并发数
- 修改后立即生效（无需重启）
- 并发数范围限制在 1-10
- 设置保存到后端持久化

### 子任务 2：Redis 界面体验优化

**目标**：完善 Redis 管理的细节体验。

**技术方案**：
- 搜索历史：`SearchFilter` 组件增加搜索历史记录（localStorage 存储最近10条）
- Key 统计：在 Redis 页脚或监控面板增加 Key 数量按类型的统计饼图/柱状图
- 批量导入：增加 Redis 数据导入功能（JSON/CSV 格式批量写入）

**验收标准**：
- 搜索输入框支持历史记录下拉
- 监控面板展示 Key 类型分布
- 批量导入支持 JSON/CSV 格式

### 子任务 3：SQL 控制台体验优化

**目标**：完善 SQL 控制台的细节体验。

**技术方案**：
- 查询历史增强：`SqlHistoryPanel` 增加按数据库/时间范围筛选
- 结果表格优化：`SqlResults` 增加固定列（首列固定）、列宽拖拽调整
- 快捷键完善：`SqlEditor` 增加 Ctrl+Enter 执行选中文本、Ctrl+Shift+F 全局格式化

**验收标准**：
- 查询历史支持筛选
- 结果表格支持固定列和列宽调整
- 快捷键按预期工作

### 子任务 4：测试与收尾

- 编写并发控制功能的单元测试和集成测试
- 编写 Redis/SQL 体验优化的单元测试
