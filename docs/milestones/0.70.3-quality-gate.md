# 0.70.3: 测试补全 + 文档重写 + 全量 review/优化

## Context

M82a–M82c（0.70.0–0.70.2）打通 SIP 电话全链路（信令/音频/视频/录音/抓包/CDR/质量监控）并收口了缺陷池 9 条遗留 bug。至此功能已稳定。本阶段在功能稳定后做**整仓库质量收口**（范围是整个 REX 代码库，不限于 SIP）：补齐全仓库单元测试与集成测试、基于当前实际实现重写文档、补全/修正代码注释、按 dev-flow 步骤4/5 维度全量 review + 简化、对媒体通道等热点做压测验证。

版本类型：minor（质量收口，无破坏性变更，向后兼容；新增测试与文档、清理冗余，不改变对外行为）

> 注：M82e（0.70.4）将做 SIP 资源「按名称管理 + 多账户切换」的结构性改造，依赖本里程碑完成后的稳定基线。本里程碑不引入该数据模型变更。

## 产品边界

### 本阶段做什么
- **测试补全**：为当前 0 个 `#[cfg(test)]` 模块的 crate（`rex-mysql`/`rex-postgresql`/`rex-sqlite`/`rex-s3`/`rex-transfer`）补充单元测试 + 集成测试；为测试薄弱的 crate（`rex-ssh`/`rex-redis`）补短板；前端 feature 覆盖补齐薄弱模块。
- **文档重写**：以代码事实为准，重写产品/开发/架构/参考文档与里程碑文档中与实际实现不符的过时描述。
- **注释更新**：补全/修正全仓库代码注释（模块头、FFI 契约、关键流程），与最终实现一致。
- **全量 review + 简化**：按 dev-flow 步骤4/5 维度过一遍整个代码库，消除重复、过度设计、拆大函数、统一风格。
- **压测**：对媒体帧吞吐/多路并发等热点做稳定性验证（不引入常驻压测脚本，仅验证并记录结论）。
- **缺陷收口**：消费缺陷池剩余 1 条 🟢（baresip FFI `arc_with_non_send_sync` clippy 警告，前序遗留）。

### 本阶段不做什么
- 不引入新用户功能（不在本里程碑新增端到端能力）。
- 不改动 Hub/Agent 版本一致模型。
- 不做 SIP 资源按名称管理 + 多账户切换（属 M82e）。
- 不改动 M82b/M82c 已稳定的媒体通道契约。
- 不引入多用户、RBAC、企业协作。

## 子任务详细设计

### 1 后端测试补全（0 测试 crate）

- **功能目标**：为 `rex-mysql`/`rex-postgresql`/`rex-sqlite`/`rex-s3`/`rex-transfer` 补齐测试，使全仓库每个 crate 至少具备覆盖核心路径的 `#[cfg(test)]` 模块（参考 `rex-hub`/`rex-sip` 既有测试风格，依赖走 `workspace = true`）。
- **文件结构**：
  - `crates/rex-sqlite/src/*.rs`（改）：SQL 构造/参数化查询/错误映射单测。
  - `crates/rex-mysql/src/*.rs`、`crates/rex-postgresql/src/*.rs`（改）：方言 SQL 生成、连接分发逻辑单测（可 mock 驱动，不依赖真实 DB）。
  - `crates/rex-s3/src/*.rs`（改）：bucket/prefix 解析、multipart 续传分片计算、URL 签名单测。
  - `crates/rex-transfer/src/*.rs`（改）：`FileConnector` trait 实现、并发/续传调度、冲突处理单测（用内存/tempfile 实现 trait 做集成测试）。
- **接口设计**：不改对外 API，仅增 `#[cfg(test)] mod tests`。
- **测试标准**：每个新增 crate 有可运行测试且 `cargo test -p <crate>` 通过；核心路径（SQL 生成/参数化/S3 分片/传输调度）有断言。
