# 0.70.0: SIP 电话资源基础（信令打通 + Agent 链式 UA + 资源模型）

## Context

M81（v0.69.0）完成 SQL 查询保存、SSH 初始化脚本与覆盖率 90% 收尾。当前产品支持 7 种资源协议（SSH/SFTP/MySQL/PostgreSQL/Redis/SQLite/S3），均为「连接远端服务并展示数据」类协议。本里程碑引入第 8 种资源类型 **`sip`（SIP 电话）**——它本质是「在 Hub/Agent 端起一个 SIP UA（用户代理），与远端 SIP 服务器协商通话」。

本阶段只打通信令层：能发起、接听、挂断、保持/恢复、转 DTMF 一通电话，并能在前端拨号盘上操作、看到通话状态。音频流（浏览器实时听/说）与通话记录/录音/抓包/展示图分别放到紧接的 0.70.1 / 0.70.2（M82b / M82c），不在此里程碑范围。

版本类型：minor（新增一种资源协议，向后兼容，无破坏性变更）

## 产品边界

### 本阶段做什么
- 新增 `sip` 资源协议（第 8 种），资源模型与向导支持 SIP 配置（SIP 服务器地址/端口、账号、密码、认证方式、显示名/号码）。
- `crates/rex-sip`：基于 **baresip（C 库，官方全平台支持：Linux/Windows 10+/macOS/Android/iOS）** 进程内 FFI 封装，**用 bindgen 自动生成绑定**（直接绑 baresip 本体，版本跟上游，不用跟不上游的 `baresip-rs` 封装）；提供安全的 `SipUa` API 与事件流。Hub 与 Agent 共用此 crate，分别当 UA₁/UA₂。构建用 git submodule 固定 baresip **最新 release tag**（v4.10.0）+ 其依赖库 libre（独立仓库 `baresip/re`，同样固定 release tag）+ `build.rs` 调 **CMake**（baresip v4.x 改用 CMake，非旧版 GNU Make）编译 libre/libbaresip 静态链；全平台可复现。
- Hub 侧 UA₁ + `/ws/sip` 控制/事件消息通道（复用 terminal_ws 的 `/ws` 范式：query 带 token+resourceId，连接后纯 JSON 帧）。
- Agent 侧 UA₂：经现有 WebSocket 隧道（`agent_ws.rs` 的 channel_id 多路复用 + binary 帧前 4 字节 channelId）链式转发 SIP 流量，内网 SIP 服务器由 Agent 出网。Agent 内跑 UA₂，用自身内网 IP 做 `Contact`/`Via`/`SDP c=`，从根本上规避「Hub IP ≠ Agent IP 透明转发导致的信令/回呼失败」问题。
- 前端 `features/sip/`：拨号盘（Dialpad）+ 通话状态组件（来电/通话中/保持/挂断/转 DTMF），复用设计 token。
- 后端持久化 SIP 注册状态、通话状态事件，供前端订阅。

### 本阶段不做什么
- 不实现浏览器实时音频（RTP→Opus→WebSocket、麦克风回传）——属 0.70.1（M82b）。M82a 的 `SipUa` 音频回调先留空桩，但接口预留 PCM/Opus 钩子。
- 不实现通话记录(CDR)、录音、信令抓包、展示图——属 0.70.2（M82c）。
- 不引入多用户、RBAC、企业协作（违反单用户自托管定位）。
- 不改变 Hub/Agent 版本一致模型。
- 不改动现有 7 种协议的行为。

## 子任务详细设计

### 1 `crates/rex-sip`：baresip 进程内 FFI 封装

- **功能目标**：用 **baresip（C 库，官方全平台：Linux/Windows 10+/macOS/Android/iOS）** 进程内 FFI 封装安全的 `SipUa`，对外暴露 register/dial/answer/hangup/hold/unhold/dtmf 与注册状态/来电/通话状态事件流。Hub、Agent 共用。用 **bindgen 直接绑 baresip 本体**（版本跟上游 release），不用跟不上游的 `baresip-rs` 封装 crate。
- **文件结构**：
  - `crates/rex-sip/` 新 crate（`Cargo.toml` 加 `rex-sip = { path = "crates/rex-sip" }` 到 workspace.dependencies；加 `bindgen = { workspace = true }`、构建期依赖 `cc`/`pkg-config`）
  - `.gitmodules`：两个 submodule，均**固定到最新 release tag**（不跟踪 main/HEAD），`git submodule update --init --recursive` 拉取：
    - `crates/rex-sip/baresip` → `https://github.com/baresip/baresip`（v4.10.0），其 C 库为 libbaresip
    - `crates/rex-sip/re` → `https://github.com/baresip/re`（libre，baresip 的依赖库，独立仓库**非** baresip 子模块）
  - `crates/rex-sip/build.rs`：调 **CMake**（baresip v4.x 构建系统已切换为 CMake，旧版 `mk/` Make 体系已弃用）编译 libre/libbaresip 静态链，再跑 bindgen 由 `baresip.h`/`ua.h`/`sip.h` 等头文件生成 `bindings.rs`；`cargo:rustc-link-lib` 链静态库 + 系统库（pthread/openssl/...）
  - `crates/rex-sip/src/lib.rs`（`SipUa`、`SipEvent`、`SipConfig` 公开类型；include! 生成的 bindings）
  - `crates/rex-sip/src/ua.rs`（基于 baresip FFI 的安全封装：baresip 事件循环跑在独立 OS 线程，经 channel 把事件回主异步运行时；register/dial/... 经 FFI 调 baresip）
  - `crates/rex-sip/src/mock.rs`（测试/无真栈的 `MockSipUa` 实现，供 Hub/Agent handler 单测；真链路需真 SIP server 时单测走 Mock）
- **接口设计**：
  ```rust
  pub struct SipConfig { pub server: String, pub port: u16, pub username: String,
                         pub password: Option<String>, pub display_name: Option<String>,
                         pub transport: SipTransport /* udp/tcp/tls */ }
  pub enum SipEvent { Registered, RegistrationFailed(String), IncomingCall{ call_id: String, from: String },
                      CallState{ call_id: String, state: CallState }, Message{ raw: String } }
  pub enum CallState { Ringing | Active | Held | Ended }
  // 抽象 trait：baresip 真实现 + 测试用 Mock 实现
  #[async_trait]
  pub trait SipUaTrait {
    async fn register(&self) -> anyhow::Result<()>;
    async fn dial(&self, dest: &str) -> anyhow::Result<String>;
    async fn answer(&self, call_id: &str) -> anyhow::Result<()>;
    async fn hangup(&self, call_id: &str) -> anyhow::Result<()>;
    async fn hold(&self, call_id: &str) -> anyhow::Result<()>;
    async fn unhold(&self, call_id: &str) -> anyhow::Result<()>;
    async fn dtmf(&self, call_id: &str, digit: char) -> anyhow::Result<()>;
    fn events(&self) -> mpsc::Receiver<SipEvent>;
    // 音频钩子（M82b 使用，M82a 留空桩，接口预留）：
    fn on_rtp(&self, _cb: impl FnMut(&[u8] /*pcm*/)) { /* no-op in 0.70.0 */ }
  }
  pub struct SipUa; // 包装 baresip 真实现，构造函数选择真/ Mock
  ```
- **集成策略（已确认：baresip + bindgen 全平台）**：baresip 官方支持全平台（Windows 10+ mingw/VS2022、Linux、macOS、Android、iOS），满足「必须支持 Windows」硬约束；用 bindgen 直接绑 baresip 本体（自动跟最新 release 头文件），避免 `baresip-rs` 封装跟不上游的问题。构建链：git submodule 固定最新 release tag（baresip v4.10.0 + libre 对应 release）→ `build.rs` 调 CMake 编静态库 → bindgen 生成绑定。M82b 媒体层（RTP→Opus→WebSocket）本就要在 baresip 事件线程里自写音频回调接管，进程内 FFI 是获取原始 RTP 帧的前提，故 baresip FFI 是正确选择。
- **后端流程**：`SipUa` 在独立 OS 线程起 baresip 主循环（加载 config：SIP 账号/服务器/传输）；`register` 发起 REGISTER；baresip 事件（注册成功/来电/通话状态）经 channel 回主异步运行时；`dial`/`answer`/... 经 FFI 转调 baresip API 并回填 `call_id`。
- **测试标准**：`rex-sip` 增纯逻辑单测（config 解析、call_id 生成、事件枚举 round-trip、MockUa 行为）；`cargo build`/`cargo test` 全绿为门禁（CI 能编静态库 + bindgen）；真机拨通在子任务 #7 联调验证（需本地 baresip 测试 server 或公开测试 SIP 服务）。
- **提交信息**：`feat: add rex-sip crate wrapping baresip via bindgen FFI (0.70.0 #1)`

### 2 资源模型加 `sip` 协议

- **功能目标**：资源协议枚举支持 `sip`；Hub 读资源时按 `protocol` 分支解析 SIP 特有配置（服务器/端口/账号/密码/显示名/传输方式），从 `config_json`（AES 加密）解密。
- **文件结构**：
  - `crates/rex-hub/src/resource_conn.rs`（新增 `load_sip_conn` 或在通用 `load_resource_conn` 按 protocol 分支；参考 `terminal_ws.rs:load_resource_conn` 的 SSH 解析范式）
  - `crates/rex-hub/src/db.rs`（`get_resource` 返回的 `protocol` 字段已是字符串，无需改 schema；仅确保 `sip` 不被校验拒绝）
  - `crates/rex-hub/src/resource_api.rs`（创建/校验资源时允许 `protocol=="sip"`，默认端口 5060；参考 line 277 match、line 467 默认端口逻辑）
- **接口设计**（数据模型）：`protocol` 字符串新增值 `"sip"`；`config_json` 字段 `{ server, port?, username, password?, displayName?, transport?("udp"|"tcp"|"tls") }`（password 经 crypto 加密存储，复用现有 encrypt 链路；匿名注册无需 password，故 password 为可选）。
- **后端流程**：`load_resource_conn`（或新 `load_sip_conn`）按 `resource.protocol` 匹配 `sip` → 解密 config_json → 组装 `SipConfig`。非 `sip` 协议保持原行为。
- **测试标准**：`db.rs`/`resource_conn.rs` 增单测：插入 `sip` 协议资源、读出解析出正确的 `SipConfig`（含加密往返）；非 sip 协议不受影响。
- **提交信息**：`feat: add sip protocol to resource model and config parsing (0.70.0 #2)`

### 3 Hub UA₁ + `/ws/sip` 控制/事件消息模型

- **功能目标**：Hub 起 `SipUa`（UA₁），通过 `/ws/sip` 与前端交互。前端发控制指令，Hub 回推事件。
- **文件结构**：
  - `crates/rex-hub/src/sip_ws.rs`（新增，范式镜像 `terminal_ws.rs`：`ws_handler(Query(resource_id), State)` → `handle_socket` → 直连/agent 分支）
  - `crates/rex-hub/src/rex-hub.rs:254` 附近注册 `.route("/ws/sip", axum::routing::get(sip_ws::ws_handler))`
- **接口设计**（WebSocket 文本帧，JSON，tag=`type`）：
  - 浏览器 → Hub 控制：`{type:"sip.dial", payload:{destination}}`、`{type:"sip.answer", payload:{callId}}`、`{type:"sip.hangup", payload:{callId}}`、`{type:"sip.hold", payload:{callId}}`、`{type:"sip.unhold", payload:{callId}}`、`{type:"sip.dtmf", payload:{callId,digit}}`、`{type:"ping"}`
  - Hub → 浏览器事件：`{type:"sip.registered"}`、`{type:"sip.registration_failed", payload:{reason}}`、`{type:"sip.incoming", payload:{callId,from}}`、`{type:"sip.call_state", payload:{callId,state}}`、`{type:"sip.sip_message", payload:{raw}}`、`{type:"sip.error", payload:{message}}`
  - 鉴权复用 terminal_ws 的 JWT query token 范式。
- **后端流程**：`handle_socket` 读资源 → `load_resource_conn` 拿 `SipConfig` → `SipUa::new`+`register` → 注册成功推 `sip.registered`；收 `SipEvent` 流映射为对应事件帧推前端；收前端控制帧转调 `SipUa` 方法。`use_agent` 时转 `handle_agent_sip`（见 #4）。
- **测试标准**：`sip_ws.rs` 用 mock `SipUa`（或 trait 抽象便于测试）做 handler 单测：拨号指令触发 `dial`、来电事件转 `sip.incoming` 帧；构建 `cargo check` 通过。
- **提交信息**：`feat: hub SipUa + /ws/sip control/event channel (0.70.0 #3)`

### 4 Agent UA₂：隧道链式转发

- **功能目标**：SIP 服务器在 Agent 内网时，Agent 内跑 `SipUa`（UA₂），经现有 WebSocket 隧道（channel_id 多路复用、binary 帧前 4 字节 channelId）与 Hub 交换 SIP 流量。
- **文件结构**：
  - `crates/rex-agent/src/agent_ws.rs`（`handle_connect` 收到 `ConnectRequest{protocol:"sip",...}` 时，起一个内网 `SipUa`（UA₂），其收发字节经 `LocalChannel.data_tx` / 隧道 binary 帧回 Hub；复用现有 channel 管理 `:211-230` 与 binary 帧解析 `:430+`）
  - `crates/rex-agent/Cargo.toml`（加 `rex-sip = { workspace = true }`，使 Agent 能跑 UA₂）
  - `crates/rex-hub/src/sip_ws.rs` 的 `handle_agent_sip`：Hub 侧 UA₁ 与前端对话，同时将 UA₁ 的 SIP 字节流（Hub↔SIP-server 这段由 Agent 代理）经 tunnel binary 帧转发给 Agent 的 UA₂
- **接口设计**：复用 `agent_ws.rs` 现有 `AgentEvent::Bytes(frame)`（frame = 4 字节 channelId + payload）与 `ConnectRequest{protocol}`。Hub→Agent 的 connect payload 增加 `protocol:"sip"` 分支（现有终端总是 `"ssh"`）。Agent 内 UA₂ 的 `Contact`/`Via`/`SDP c=` 自动填 Agent 内网 IP——因为 UA₂ 进程就在 Agent 上，无需任何 IP 改写。
- **后端流程**：前端拨号 → Hub UA₁ → 经隧道发 Agent → Agent UA₂ 真正面向内网 SIP server → 200 OK/ACK/RTP 由 UA₂ 用自身 IP 完成 → 媒体/信令字节经隧道回 Hub → Hub 转前端。每段都是 UA 对 UA 的真实对话，无透明 IP 搬运。
- **测试标准**：Agent 侧 `handle_connect` 对 `protocol:"sip"` 起 UA₂ 的单测（mock 隧道 channel，断言字节经 data_tx 进出）；Hub `handle_agent_sip` 隧道帧 ↔ UA₁ 事件映射单测。
- **提交信息**：`feat: agent SipUa (UA2) over existing channel-multiplexed tunnel (0.70.0 #4)`

## 设计核对点

- 单用户、自托管定位不被破坏（SIP 资源仍属单一用户本地管理，无多租户）。
- 不引入 RBAC/多用户/企业协作。
- 资源模型仅在既有 `protocol` 字符串枚举上增 `sip` 值，不改 schema，向后兼容。
