# v0.70.8: Hub / Agent 服务化管理（CLI 子命令 + 开机自启）

## Context

前序阶段（v0.70.0–v0.70.7）完成了 SIP 电话、统一隧道架构、SQL 资源模型合并，产品功能已稳定。当前 Hub / Agent 两个二进制仍以「env 变量 + 直接运行可执行文件」的方式启动：配置靠 `REX_PORT` / `REX_DATA_DIR` / `REX_HUB_URL` / `REX_AGENT_TOKEN` 等环境变量，启动方式是手工 `./rex-hub`，没有子命令入口，也没有任何开机自启机制。

本阶段补齐自托管运维最基础的一环：**统一的 CLI 子命令入口** + **一键注册为操作系统服务实现开机自启**。这让 `rex-hub` / `rex-agent` 的运维体验和 Xshell / Navicat 这类成熟工具的「安装为服务」对齐（对标 PRODUCT §10 的「部署/运维」基线），也是后续容器化之外最自然的二进制部署形态。

版本类型：minor（新增功能，向后兼容。现有 env 变量配置全部保留，行为不变；只是新增 `run`/`version`/`service` 子命令入口，默认子命令即原有启动逻辑）。

## 产品边界

本阶段做什么：
- 为 Hub / Agent 引入基于 `clap` derive 的 CLI 子命令：`run`（默认，启动 supervisor+worker）、`version`、`service install/uninstall/start/stop/restart/status`。
- 实现「一键注册为系统服务」并开机自启：
  - Linux → systemd（user 与 system 两种 scope）。
  - macOS → launchd（user `LaunchAgents` 与 system `LaunchDaemons` 两种 scope）。
- `service install` 把当前相关 env 变量（Hub：`REX_PORT` / `REX_DATA_DIR` / `REX_STATIC_DIR`；Agent：`REX_HUB_URL` / `REX_AGENT_TOKEN`）写入生成的单元文件，使服务以与当前手工启动一致的方式运行。
- 更新部署文档，说明二进制部署下的 `service install` 与开机自启。

本阶段不做什么：
- 不改动 supervisor + worker 进程模型、退出码语义、更新/回滚机制（沿用 `rex-common::supervisor` 与 `rex-agent::supervisor`）。
- 不实现 Windows 服务注册自动化：Windows 仅给出带外指引（nssm / 任务计划程序），CLI 在 Windows 上对这些子命令返回明确「unsupported」错误与提示。原因：Windows 已有 supervisor.exe 自我复制模型，自动化注册需 `sc`/`nssm` 且 CI 无法验证，超出本里程碑可测范围。
- 不引入复杂的多格式/分层配置：仅新增一个**可选的 YAML 配置文件**作为 env 变量的补充来源（数据目录下 `config.yaml` / `agent.yaml`），**env 变量优先**；原有 env 配置方式与行为完全保留，业务代码零改动。
- 不触碰前端、不改产品语义、不引入多用户/RBAC 概念。

### 实现相对原设计的扩充（实现期已落地，纳入本里程碑范围）

开发过程中在保持「产品边界」不变的前提下，做了以下原计划未单列、但属同一运维目标的合理扩充，均已写入代码并通过质量门禁（fmt/clippy/test 全绿）：

1. **新增 `stop` 子命令 + `rex-common::process` 模块**：原计划 CLI 只有 `run`/`version`/`service`。实际新增了单实例互斥（pid 文件 `<data_dir>/rex-<hub|agent>.pid`，保证一个环境只有一个 agent/hub，陈旧 pidfile 自动清理）、`--background` 后台运行（daemonize：Unix 双 fork + `setsid` 脱离终端，日志重定向到数据目录 `rex-*.log`）、以及 `rex-hub stop` / `rex-agent stop` 终止命令（读 pidfile 发 `SIGTERM` 并清理）。跨平台进程存活检测（Unix `kill(pid,0)` / Windows `OpenProcess`）。
2. **`run` 子命令带显式参数（`RunOpts`）**：原计划「run 不带参数、配置完全走 env」。实际 `run` 支持 `--single`、`--background`、`--port`、`--data_dir`、`--static_dir`(Hub)、`--hub_url`、`--token`(Agent)；参数优先级为 **命令行 > env > 配置文件**，参数经 env 透明传递给 worker/supervisor 子进程。`--single` 直接跑 worker、无 supervisor、自动更新不可用（Agent 显式 `REX_AUTO_UPDATE=false`）。
3. **可选 YAML 配置文件（`config.rs`）已落地**：原计划列为「可选补充」。实际新增 `rex-common::config` 模块，`apply_config_env(kind)` 在启动早期（spawn worker 前、创建 tokio runtime 前）读取 `config.yaml`/`agent.yaml`，仅当对应 env 未设置时写入 env，env 始终优先，业务代码零改动。

## 子任务详细设计

### 1 共享 CLI 框架（`rex-common::cli`）

- **功能目标**：定义 Hub / Agent 共用的命令行结构，提供 `dispatch()` 入口，使两个二进制只需传入自己的 `run` 闭包（启动逻辑）即可复用全部子命令与 `service` 处理。
- **文件结构**（创建 / 修改）：
  - 新建 `crates/rex-common/src/cli.rs`
  - 在 `crates/rex-common/src/lib.rs` 导出 `pub mod cli;`
- **接口设计**（clap derive 数据模型，定义在 `rex-common::cli`）：
  ```rust
  #[derive(Parser)]
  #[command(author, version, about = "REX Hub / Agent")]
  pub struct Cli {
      #[command(subcommand)]
      pub command: Option<Commands>, // None = 默认 run
  }

  #[derive(Subcommand)]
  pub enum Commands {
      Run(RunOpts),              // 启动服务（默认；等价直接运行可执行文件）
      Stop,                      // 读 pid 文件发送终止信号（见子任务 1b）
      Version,                   // 打印版本号（含短 git hash）
      Service(ServiceCmd),       // 注册/管理操作系统服务（开机自启）
  }

  #[derive(Args, Default)]
  pub struct RunOpts {
      --single,                  // 单进程模式：直接 worker，无 supervisor，自动更新不可用
      --background,              // 后台运行：daemonize + 日志重定向到数据目录 rex-*.log
      --port, --data_dir, --static_dir,   // Hub 相关
      --hub_url, --token,        // Agent 相关
  }

  pub fn dispatch(cli: Cli, kind: ServiceKind,
                  run: impl FnOnce(&RunOpts) -> anyhow::Result<()>) -> anyhow::Result<()>
  ```
  - 配置优先级：**命令行参数 > 环境变量 > 配置文件**（见子任务 5）。`RunOpts` 字段经 `std::env::set_var` 写回 env，由 supervisor/worker 子进程继承。
  - `None` 或 `Some(Run(_))` → 调用 `run(opts)`（各二进制自己的 supervisor+worker 启动逻辑）。
  - `Some(Stop)` → 调用 `crate::process::stop(kind)` 打印结果后退出。
  - `Some(Version)` → `println!("rex-{} {}", kind.as_str(), full_version())`（`full_version()` 含 `build.rs` 注入的短 git hash）后退出。
  - `Some(Service(cmd))` → 调用 `rex_common::service::handle(kind, cmd)`。
  - 设计取舍（相对原设计调整）：原计划「run 不带参数、配置完全走 env」；实际为运维便利放开显式参数，参数仅做 env 透传，不产生业务代码分支，仍与进程模型一致。
- **交互设计**：无前端，纯命令行。
- **后端流程**：`main()` 第一步 `Cli::parse()`（clap 自动处理 `--help`/`--version`），再 `dispatch`。
- **测试标准**：clap 解析单测（无参→默认 Run；`version`；`run --single --background`；`run --port 8080`；`stop`；`service install --system`/`--name`）；`dispatch` 单测（Run/Version/Service 调用对应路径；`stop` 不误调 `run` 闭包）；`full_version` 格式回退单测。
- **提交信息**：`feat(cli): add shared clap CLI framework for hub/agent`

### 1b 进程管理（`rex-common::process`，与子任务 1 同期实现）

- **功能目标**：支撑 `stop` 子命令与单实例约束——同一 `data_dir` 只允许一个 Hub / Agent 运行（一个环境只能有一个 agent），并提供后台运行（daemonize）能力。
- **文件结构**（创建）：
  - 新建 `crates/rex-common/src/process.rs`
  - 在 `lib.rs` 导出 `pub mod process;`
  - 依赖：`[target.'cfg(unix)'.dependencies] libc = "0.2"` 与 `[target.'cfg(windows)'.dependencies] windows-sys`（跨平台进程存活检测 / 终止）
- **接口设计**：
  ```rust
  pub fn pid_path(kind: ServiceKind) -> PathBuf
  pub fn ensure_single_instance(kind: ServiceKind) -> Result<()>  // 已有存活实例则拒绝启动
  pub fn write_pid_file(kind: ServiceKind) -> Result<PathBuf>     // 写 pid + atexit 兜底清理
  pub fn stop(kind: ServiceKind) -> String                        // 读 pidfile → SIGTERM → 清理
  pub fn daemonize() -> Result<()>                                // 后台脱离终端（Unix 双 fork+setsid）
  ```
- **后端流程**：`run_service` 启动早期依次调用 `apply_config_env` → `ensure_single_instance` → 写回 `RunOpts` 到 env →（可选）`daemonize` → `write_pid_file` → 分流 supervisor/worker。
- **测试标准**：`read_pid_file`（缺失/存在/垃圾值）、`pid_path` 含 kind、`ensure_single_instance` 自身 pid 不冲突。
- **提交信息**：`feat(process): add single-instance pidfile, daemonize and stop`

### 2 服务安装抽象（`rex-common::service`）

- **功能目标**：跨平台生成操作系统服务单元并注册/启停，使「开机自启」成为一条命令。生成逻辑与「实际执行 systemctl/launchctl」解耦，便于单测。
- **文件结构**（创建）：
  - 新建 `crates/rex-common/src/service.rs`
  - 在 `lib.rs` 导出 `pub mod service;`
- **接口设计**（定义在 `rex-common::service`）：
  ```rust
  pub enum ServiceKind { Hub, Agent }   // as_str / default_name / launchd_label / relevant_env_keys
  pub enum ServiceScope { User, System }
  pub enum ServicePlatform { Linux, Macos, Other }

  pub struct InstallConfig { kind: ServiceKind, name: String, scope: ServiceScope, exe: PathBuf }

  #[derive(Args)] pub struct ServiceOpts { #[arg(long)] system: bool, #[arg(long)] name: Option<String> }
  #[derive(Subcommand)] pub enum ServiceCmd {
      Install(ServiceOpts), Uninstall(ServiceOpts), Start(ServiceOpts),
      Stop(ServiceOpts), Restart(ServiceOpts), Status(ServiceOpts),
  }

  pub fn detect_platform() -> ServicePlatform
  pub fn render_systemd_unit(cfg: &InstallConfig, env: &[(String,String)]) -> String  // 纯函数
  pub fn render_launchd_plist(cfg: &InstallConfig, env: &[(String,String)]) -> String // 纯函数
  pub fn install(cfg: &InstallConfig) -> Result<String>
  pub fn uninstall(kind, name, scope) -> Result<String>
  pub fn start(kind, name, scope) -> Result<String>
  pub fn stop(kind, name, scope) -> Result<String>
  pub fn restart(kind, name, scope) -> Result<String>
  pub fn status(kind, name, scope) -> String
  pub fn handle(kind: ServiceKind, cmd: ServiceCmd) -> anyhow::Result<()>   // dispatch 调用
  ```
  `render_*` 为纯函数，额外接收 `env: &[(String,String)]`（调用方经 `collect_env(kind)` 从进程 env 收集）以便单测传入显式 env。`install/uninstall/start/stop/restart/status` 按 `detect_platform()` 分发到 systemd / launchd / Other（Unsupported）。
- **systemd 单元生成**：
  ```ini
  [Unit]
  Description=REX Hub
  After=network.target

  [Service]
  Type=simple
  ExecStart=<exe>
  Environment=REX_PORT=3000
  Environment=REX_DATA_DIR=/home/<user>/.rex
  Restart=on-failure
  RestartSec=2

  [Install]
  WantedBy=multi-user.target      # system
  # WantedBy=default.target       # user
  ```
  - env 行来自当前进程 env（`REX_PORT`/`REX_DATA_DIR`/`REX_STATIC_DIR` for Hub；`REX_HUB_URL`/`REX_AGENT_TOKEN` for Agent），仅写入非空的变量，保持与手工启动一致。
  - user scope 路径：`$XDG_CONFIG_HOME/systemd/user/rex-<kind>.service`（默认 `~/.config/systemd/user/`）；system scope 路径：`/etc/systemd/system/rex-<kind>.service`。
  - `install()` 流程：`daemon-reload` → `enable` → `start`（user 模式加 `--user`）。
- **launchd plist 生成**：
  ```xml
  <?xml version="1.0" encoding="UTF-8"?>
  <!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
  <plist version="1.0">
  <dict>
    <key>Label</key><string>com.rex.<kind></string>
    <key>ProgramArguments</key><array><string><exe></string></array>
    <key>EnvironmentVariables</key><dict>
      <key>REX_PORT</key><string>3000</string>...
    </dict>
    <key>RunAtLoad</key><true/>
    <key>KeepAlive</key><true/>
    <key>StandardErrorPath</key><string>~/Library/Logs/rex-<kind>.log</string>
    <key>StandardOutPath</key><string>~/Library/Logs/rex-<kind>.log</string>
  </dict>
  </plist>
  ```
  - user scope：`~/Library/LaunchAgents/com.rex.<kind>.plist`；system scope：`/Library/LaunchDaemons/com.rex.<kind>.plist`（需 root）。
  - `install()`：`launchctl load <path>`（user）/ `launchctl load -w`（system，谨慎）+ `RunAtLoad` 已保证开机自启。
  - `start/stop`：`launchctl start/stop <label>`；`status`：`launchctl list | grep <label>` 解析。
- **Other 平台（如 Windows）**：`install`/`uninstall`/`start`/`stop`/`restart`/`status` 全部经 `unsupported()` 返回 `anyhow` 错误，消息含指引（用 nssm 或任务计划程序）。
- **错误处理**：用 `anyhow::Result`；执行外部命令失败返回带命令与 stderr 的 `ServiceError`。`ServiceError` 在 `rex-common` 内定义为 `anyhow` 上下文友好类型（或仅用 `anyhow::anyhow!` + 上下文）。
- **测试标准**：
  - `detect_platform()` 在 CI（Linux）返回 `Linux`（用 cfg 也可）。
  - `render_systemd_unit` 输出含 `[Unit]`/`ExecStart=<exe>`/`Restart=on-failure`/`WantedBy=` 且 user 与 system 的 `WantedBy` 不同。
  - `render_launchd_plist` 输出是合法 XML（用 `std::str` 校验含 `<plist` 与 `RunAtLoad`，并能被 `plist` 解析库或简单结构校验；若无 plist 库则用 XML 片段断言 + 标签配对检查）。
  - env 注入：传入 `REX_PORT=3000` 时单元/plist 含对应行。
- **提交信息**：`feat(service): add cross-platform service install (systemd + launchd)`
- **设计原则**：生成逻辑（render_*）与执行（install/start/...）分离，render 纯函数易测；执行部分在测试中以 `cfg(unix)` 跳过真实 `systemctl`，仅验证路径解析与命令构造。

### 3 Hub CLI 接入

- **功能目标**：`rex-hub` 入口先用 clap 解析，再分发到 run/version/service。
- **文件结构**（修改）：`crates/rex-hub/src/rex-hub.rs`
- **接口设计**：重构 `main()`：
  ```rust
  fn main() {
      let cli = rex_common::cli::Cli::parse();
      let kind = rex_common::service::ServiceKind::Hub;
      let result = rex_common::cli::dispatch(cli, kind, |_opts| {
          // 保留原有 supervisor/worker 分支
          if std::env::var("REX_WORKER").is_err() {
              supervisor_main();
          } else {
              worker_main();
          }
      });
      if let Err(e) = result {
          eprintln!("Error: {e:#}");
          std::process::exit(1);
      }
  }
  ```
  - `supervisor_main()` / `worker_main()` 保持原样（含 tracing 初始化、data_dir、端口解析）。
  - `version` / `service` 由 `dispatch` 处理，不再需要 `main` 自己判断 env（但 `REX_WORKER` 分支仍在 `run` 闭包内，保证 worker 子进程由 supervisor 以 `REX_WORKER=1` 拉起时走 worker 路径）。
- **交互设计**：无前端。
- **后端流程**：见上。
- **测试标准**：复用 `rex-common::cli` 解析测试；Hub 集成主要靠 `cargo build` 跑通 + `rex-hub --help` / `rex-hub version` 手动验证（CI 可加一个 `cargo run --bin rex-hub -- --version` 烟雾测试，可选）。
- **提交信息**：`feat(hub): wire clap CLI into hub entrypoint`

## 设计核对点

- 是否仍遵守「单用户、自托管、无 RBAC」：是，CLI/服务仅运维本机进程。

- 文件传输是否不经浏览器：不涉及。
- 是否引入不该有的概念：否。
- 是否跳阶段：否，本功能为已稳定产品的运维增强，属 minor。
- 版本一致：Hub/Agent 共用同一 `CARGO_PKG_VERSION`，CLI 与 service 模块在 `rex-common`，天然一致。
- 平台边界：Linux systemd + macOS launchd 实现并测试生成逻辑；Windows 仅返回 Unsupported 错误，不崩溃。
