# M17 步骤2：设计核对报告

## 审查维度

### 1. 产品定位

- [x] **单用户** — 无多用户、RBAC
- [x] **自托管** — TLS 证书由用户自行管理
- [x] **深色优先** — 不涉及 UI 变更

### 2. 架构一致性

- [x] **进程模型** — TLS 在 Hub 主进程处理，不影响 supervisor/worker
- [x] **单二进制** — TLS 逻辑编译进 Hub 二进制
- [x] **Agent ↔ Hub** — WSS 复用现有 WebSocket 连接，仅加 TLS 层

### 3. 功能边界

| 检查项 | 结论 |
|--------|------|
| M17 做什么清晰？ | ✅ Hub TLS + Agent WSS + Docker 配置 |
| M17 不做什么明确？ | ✅ 不做证书续期 UI、不做 mTLS |
| 是否引入后续里程碑功能？ | ❌ 无 |
| 是否跳阶段？ | ❌ 无 |

### 4. 设计合理性

| 设计点 | 评估 |
|--------|------|
| 三种证书模式（自签名/手动/ACME） | ✅ 覆盖开发到生产场景 |

| 向后兼容（默认无 TLS） | ✅ 不影响现有部署 |
| Agent insecure 模式 | ✅ 自签名开发场景必需 |
| 端口复用（同端口 HTTP/HTTPS） | ✅ 简化配置 |

### 5. 无概念污染

- [x] 无 RBAC、多用户
- [x] 无企业协作
- [x] 无 SaaS 依赖
