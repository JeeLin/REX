# 0.70.5: 缺陷池清理 + SIP 配置收口

## Context

M82e（0.70.4）完成了 SIP 资源「按名称 + 多账户」数据模型重构，将 `SipConfig`（解析后生效配置）与 `SipProfile`（accounts[] + activeAccount 存储层）分离，并修复了步骤5 首次打回的 5 个 🟡 与重跑的 3 个 🟡。

步骤5 重跑（代码审查）另发现 3 个 🟢 可选改进（类型/逻辑漂移、逃生舱、多余往返），依「🔴/🟡 打回、🟢 入缺陷池」契约记入 `docs/BUGS.md`，由本里程碑（下一个版本）统一消费收口。

本阶段是 0.70.4 的纯质量收口（patch），无新功能、无用户可见行为变化。三项均来自 0.70.4 缺陷池，目标是消除 SIP 配置层三处镜像与一处遗留逃生舱，并减少切换生效账户时的多余 GET 往返。

版本类型：patch（无新功能，仅 🟢 收口 + 重构）

## 产品边界

### 本阶段做什么
- 移除 `load_sip_conn` 中「账户 server 缺省时回退资源顶层 host」的逃生舱（模型已声明 server 完全下沉账户）。
- 抽出共享 `SipProfile` TS 类型 + 统一的「active 或 first」解析规则，消除 `load_sip_conn` / `SipPage.parseSipProfile` / `WizardModal.buildConfig` 三处镜像。
- 新增 `set_active_account` 专用后端端点，前端 `SipPage.selectAccount` 切换生效账户时不再先 `get` 全量再 `update`。

### 本阶段不做什么
- 不改动 SIP 数据模型（`SipProfile` / `SipAccount` 形状不变），不改动 `SipConfig` 线格式。
- 不改动 baresip FFI 边界、媒体通道契约、Hub/Agent 隧道帧。
- 不引入多用户、RBAC、企业协作（CLAUDE.md 硬约束）。
- 不把文件传输数据经浏览器（本次不涉及）。

## 子任务详细设计

### 1 移除 load_sip_conn 顶层 host 回退逃生舱

- **功能目标**：模型已声明 server 完全下沉到账户层（资源顶层 `host` 对 SIP 不再作为 server 来源）。移除 `load_sip_conn` 中「账户 server 为空时回退 `info.host`」的分支，使配置语义与声明一致。
- **文件结构**：
  - `crates/rex-hub/src/resource_conn.rs`：`load_sip_conn` 去掉 `server` 的 `if !active.server.is_empty() { ... } else { info.host }` 回退，直接取 `active.server`，为空即报 `sip: missing server`。
- **接口设计**：纯内部解析函数，无 API 变更。`ResourceConnInfo.host` 字段保留（其他协议仍用），但 SIP 分支不再读取它。
- **后端流程**：`load_sip_conn(info)` → 选出生效账户 → `server = active.server`（空即报错，不再回退）→ 组装 `SipConfig`。
- **测试标准**：`resource_conn` 既有用例 `load_sip_conn_account_server_defaults_to_top_level_host`（依赖回退）需调整/删除；新增/保留用例覆盖「账户 server 为空 → 报错」「账户 server 有值 → 取自身值」。
- **提交信息**：`refactor: drop sip top-level host fallback in load_sip_conn (0.70.5 #1)`

### 2 抽出共享 SipProfile TS 类型 + active/first 解析规则

- **功能目标**：前端 `SipProfile` 形状（`{ accounts[], activeAccount }`）与「取 active，不存在回退 accounts[0]」的解析规则当前在 `WizardModal.buildConfig`、`SipPage.parseSipProfile` 两处 TS 中手敲实现，与后端 `load_sip_conn` 的 Rust 规则三份镜像，存在类型/逻辑漂移风险。抽出共享 TS 类型与解析函数，集中唯一实现。
- **文件结构**：
  - `packages/rex-console-web/src/features/sip/types.ts`（新建）：`SipProfile` / `SipAccountView` / `SipAccountForm` 类型 + `resolveActiveAccount(profile): SipAccountView | undefined` 函数（active 或 first）。
  - `packages/rex-console-web/src/features/sip/SipPage.vue`：`parseSipProfile` 改用共享 `resolveActiveAccount`。
  - `packages/rex-console-web/src/features/resource/WizardModal.vue`：`buildConfig` 的 active 判定改用共享 `resolveActiveAccount`；`resourceHost()` 的生效账户派生改用共享函数。
  - `packages/rex-console-web/src/api/resources.ts`：可选补 `SipProfile` 类型导出（视调用方而定）。
- **接口设计**：仅前端类型/函数抽取，无 API 变更。注意后端 `SipAccount` serde 字段（`server`/`port`/`transport`/`username`/`password`/`displayName`/`id`）与前端视图类型对齐。
- **后端流程**：无（本子任务前端 only，但确保与 `load_sip_conn` 的「active 或 first」语义一致——后端规则保持，前端统一复用同一语义的 TS 实现）。
- **测试标准**：`WizardModal.sip.test.ts` / `SipPage.test.ts` 保持通过（序列化、生效账户切换、host 派生）；可增补一个 `types.test.ts` 覆盖 `resolveActiveAccount`（active 存在取 active、active 不存在回退 first、空 accounts 返回 undefined）。
- **提交信息**：`refactor: extract shared SipProfile types + resolveActiveAccount (0.70.5 #2)`

### 3 新增 set_active_account 端点，消除 selectAccount 多余 GET 往返

- **功能目标**：`SipPage.selectAccount` 当前先 `resourcesApi.get` 拉全量、改写 `activeAccount` 后再 `update_resource`（因后端 `update_resource` 要求全字段，`get` 用于避免覆盖其他字段）。改为调用专用 `set_active_account` 端点，仅传 `account_id`，后端读全量→改 `activeAccount`→写回，前端不再发多余 GET。
- **文件结构**：
  - `crates/rex-hub/src/resource_api.rs`：新增 `set_active_account` handler（`POST /{env_id}/resources/{resource_id}/active-account`，body `{ account_id }`）；在 `resource_routes()` 注册该路由。
  - `crates/rex-hub/src/db.rs`：新增 `set_resource_active_account(env_id, id, account_id)`——读取资源、校验 `account_id` 属于该资源的 `SipProfile.accounts`、改写 `config_json.activeAccount` 后加密写回（复用既有「读-改-写」模式，同 `update_resource`）。
  - `packages/rex-console-web/src/api/resources.ts`：新增 `setActiveAccount(envId, id, accountId)`。
  - `packages/rex-console-web/src/features/sip/SipPage.vue`：`selectAccount` 改为调用 `setActiveAccount`，移除前置 `resourcesApi.get`（保留对返回 `config_json` 的解析；若端点返回更新后的资源则直接用）。
- **接口设计**：
  - 新端点 `POST /api/environments/{env_id}/resources/{resource_id}/active-account`
  - 请求体 `{ "account_id": "a1" }`
  - 成功返回更新后的 `Resource`（config_json 为加密态或解密态，视既有约定；前端不依赖其解析结果，仅确认成功即可本地更新 `activeAccount`）。
  - 错误：account_id 不存在于该资源 → 400/404。
- **后端流程**：`set_active_account` → 读资源（解密 config_json）→ 解析 `SipProfile` → 校验 `account_id ∈ accounts` → 置 `activeAccount = account_id` → 加密写回 → 审计日志。
- **测试标准**：后端 `resource_api` 增补——有效 account_id 写回成功、无效 account_id 拒绝、非 sip 资源拒绝（或忽略，依既有协议校验）。前端 `SipPage.test.ts` 增补——`selectAccount` 调用 `setActiveAccount` 而非先 `get` 后 `update`。
- **提交信息**：`feat: add set_active_account endpoint, drop selectAccount redundant get (0.70.5 #3)`
