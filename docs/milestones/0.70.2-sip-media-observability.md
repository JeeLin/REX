# 0.70.2: 音视频增强 + 通话记录 + 录音 + 抓包 + 质量监控

## Context

M82a（0.70.0）打通 SIP 信令层；M82b（0.70.1）打通浏览器实时双向音频（原始 S16LE PCM 媒体通道）。本阶段在 M82b 的媒体通道基础上，补齐**通话可观测性与媒体能力**：浏览器侧实时视频、通话录音落盘与回放、SIP 信令抓包、通话记录（CDR）持久化、实时音视频质量监控（丢包率/延迟/抖动）。

本里程碑同时承载用户确认的**缺陷池全量收口**：M82c 之前 `docs/BUGS.md` 累积的 9 条遗留 bug（🔴×1 / 🟡×5 / 🟢×3，跨更新检查/审计/工作空间/文件/SQL/移动端/SIP 等模块）全部纳入本里程碑修复范围（见 `## Bugs`），缺陷池已清空。

版本类型：minor（新增媒体可观测性功能 + 缺陷修复，向后兼容，无破坏性变更）

> 注：M82d（0.70.3）是整个代码库的质量收口里程碑（测试补全 + 文档重写 + 全量 review/优化 + 压测）。本里程碑已按用户决策先行并入缺陷池 bug，M82d 不再重复纳入这些项。

## 产品边界

### 本阶段做什么
- **浏览器实时视频**：复用 M82b 的 `vidbridge`/`vidsrc` 同构机制（baresip 视频设备桥），前端 WebCodecs 解码 + `<video>` 播放；上行采集经 getUserMedia 视频轨，与音频共用隧道/WebSocket 帧（首字节 kind 区分媒体/信令，payload 为原始/编解码后视频字节）。
- **通话录音**：Hub 侧在通话建立后捕获媒体帧（音频 PCM / 视频帧）落盘为 mp3 / wav（复用 baresip aufile 或媒体帧捕获），前端提供回放器（进度/暂停/下载）。
- **信令抓包**：UA₁/UA₂ 两侧 SIP 报文捕获（baresip 报文日志钩子），导出为 pcap，前端回看/下载。
- **通话记录 CDR**：每通电话的起止时间/对端/时长/状态（呼叫/接听/挂断/未接）持久化（SQLite），前端表格（筛选/排序/详情），关联录音与抓包。
- **音视频质量监控**：实时采集丢包率、端到端延迟、抖动（baresip RTP 统计回调 / RTCP），前端可视化展示（通话中实时指标卡片）。
- **缺陷收口**：9 条遗留 bug 按 🔴→🟡→🟢 顺序修复（见 `## Bugs`）。

### 本阶段不做什么
- 不引入多用户、RBAC、企业协作。
- 不改变 Hub/Agent 版本一致模型。
- 不改动 M82b 已稳定的音频媒体通道契约（方向、kind 区分、PCM 格式）；视频仅扩展媒体类型，复用既有帧结构。
- 不改动信令层行为（register/dial/answer/hold/unhold/dtmf 不变）；SIP 资源「按名称管理 + 多账户切换」属 M82e，本阶段不做。
- 视频线上编码：默认维持原始边界，必要时再引入（与 M82b 音频不线上编码一致）。

## 子任务详细设计

### 1 浏览器实时视频

- **功能目标**：在 M82b 音频媒体通道基础上增加视频。baresip `vidbridge`/`vidsrc` 设备桥与 `ausrc`/`auplay` 同构，抽取/喂入原始视频帧；前端解码经 WebCodecs 渲染 `<video>`，上行 getUserMedia 视频轨采集回传。媒体帧通道复用 M82b 的 `[kind][payload]` 结构，视频增一种媒体类型（payload 为视频字节，默认原始或经浏览器原生编码）。
- **文件结构**：
  - `crates/rex-sip`（视频驱动桥，对标 `audio_bridge.rs`；`SipUaTrait` 增 `on_rtp_video` / `send_video`）
  - `crates/rex-common/src/sip_media.rs`（媒体类型区分：音频/视频，隧道帧 kind 复用）
  - `crates/rex-hub/src/sip_ws.rs` / `crates/rex-agent/src/agent_ws.rs`（媒体帧路由增视频分支）
  - `packages/rex-console-web/src/api/sipMedia.ts`（视频帧编解码辅助）
  - `packages/rex-console-web/src/features/sip/SipPage.vue`（`<video>` + 采集开关）
- **接口设计**：媒体帧通道不变（二进制帧，方向隐含）；视频经视频类型媒体帧传输。前端 `SipClient` 增 `onVideo` 回调 + `startVideo()`/`stopVideo()`。
- **前端流程**：`call_state:active` → 可选开启视频 → `<video>` 渲染下行帧；上行 getUserMedia 视频轨 → 视频帧回传。
- **测试标准**：视频帧编解码 round-trip 单测；`sip_ws`/`agent_ws` 视频媒体帧路由单测（下行/上行经 tunnel kind 无损）；前端视频帧路由、开关单测。CI 难含真摄像头/解码器，联调以本地验证为准。
- **提交信息**：`feat: sip browser real-time video over media channel (0.70.2 #1)`

### 2 通话录音

- **功能目标**：Hub 在通话建立后捕获媒体帧落盘为 mp3/wav，前端可在 CDR 详情回放、下载。
- **文件结构**：
  - `crates/rex-sip`（媒体帧捕获：音频 PCM 写入、视频帧写入；复用 aufile 或内存写入器）
  - `crates/rex-hub/src/`（录音任务管理 + 落盘路径 + 下载 API）
  - `packages/rex-console-web/src/features/sip/`（录音回放器组件）
- **接口设计**：后端录音文件静态/流式下载端点（复用 Hub 静态托管或专用 endpoint）；前端回放器 props：url/时长/状态。
- **前端流程**：CDR/通话详情 → 录音列表 → 回放（进度条/暂停/下载）。
- **测试标准**：捕获写入 round-trip（给定 PCM 序列 → 落盘字节数正确、可解析）；落盘路径/命名单测；前端回放器加载单测（mock url）。
- **提交信息**：`feat: sip call recording: hub capture to disk + web playback (0.70.2 #2)`

### 3 信令抓包

- **功能目标**：UA₁/UA₂ 两侧捕获 SIP 信令报文，导出 pcap，前端回看/下载。
- **文件结构**：
  - `crates/rex-sip`（SIP 报文日志钩子：baresip 报文日志回调捕获原始 SIP 文本/包）
  - `crates/rex-hub/src/`（抓包会话管理 + pcap 封装 + 下载端点）
  - `packages/rex-console-web/src/features/sip/`（抓包控制 + 回看/下载 UI）
- **接口设计**：pcap 为 libpcap 格式（链路类型 RAW / SIP 文本），前端按文本/十六进制回看或下载 .pcap。抓包开关随通话或按需触发。
- **前端流程**：通话详情/工具栏 → 开始抓包 → 停止 → 下载 pcap / 在线回看。
- **测试标准**：报文捕获按序记录单测；pcap 头部/包封装符合 libpcap 格式（可用解析库校验）；前端回看渲染单测（mock 文本）。
- **提交信息**：`feat: sip signaling packet capture to pcap + web viewer (0.70.2 #3)`

### 4 通话记录 CDR

- **功能目标**：每通电话持久化起止时间/对端/时长/状态；前端表格筛选/排序/详情，关联录音与抓包。
- **文件结构**：
  - `crates/rex-hub/src/db.rs`（CDR 表 + 持久化：`call_id`/`resource_id`/`peer`/`start`/`end`/`duration`/`state`/`recording_url`/`pcap_url`）
  - `crates/rex-hub/src/`（CDR 列表/详情 REST API + 筛选/排序参数）
  - `packages/rex-console-web/src/features/sip/CdrPage.vue` + `api/sip.ts`（CDR API 客户端）
- **接口设计**：`GET /api/sip/cdr?resourceId=&from=&to=&state=&page=&sort=` → 分页列表；`GET /api/sip/cdr/:id` → 详情（含录音/抓包链接）。后端 `ORDER BY time DESC, id DESC` 稳定排序。
- **前端流程**：导航/资源详情 → CDR 表格（时间/对端/时长/状态彩色标签）→ 详情抽屉（关联录音回放 + 抓包下载）。
- **测试标准**：CDR 写入（状态机驱动 call_state 事件 → 行正确）/持久化单测；API 筛选/排序/分页单测；前端表格渲染 + 详情关联单测。
- **提交信息**：`feat: sip CDR persistence + list/detail API + web table (0.70.2 #4)`

### 5 音视频质量监控

- **功能目标**：实时采集丢包率/端到端延迟/抖动并前端可视化。
- **文件结构**：
  - `crates/rex-sip`（RTP/RTCP 统计回调：丢包、抖动、RTT）
  - `crates/rex-hub/src/sip_ws.rs`（质量指标经 WebSocket 事件推浏览器）
  - `packages/rex-console-web/src/features/sip/`（实时质量指标卡片）
- **接口设计**：新增 `sip.quality` 服务端事件 `{ loss: f32, jitter: f32, rtt: f32 }`，通话中周期推送。
- **前端流程**：通话进行中 → 实时指标卡片（丢包率/延迟/抖动，数值 + 趋势）。
- **测试标准**：指标计算（给定 RTP 统计 → 指标值正确）单测；前端指标卡片渲染单测（mock 事件）。
- **提交信息**：`feat: sip real-time quality metrics (loss/jitter/rtt) + web viz (0.70.2 #5)`

## 设计核对点

- 单用户、自托管定位不被破坏（视频/录音/抓包端点仍是单一用户本地浏览器 + 服务端，无多租户）。
- 不引入 RBAC/多用户/企业协作。
- 媒体通道复用 M82b 的 `[kind][payload]` 结构，视频仅扩展媒体类型，不破坏既有音频契约。
- 录音/抓包/CDR 数据不经浏览器中转原始流（与「文件传输不经过浏览器」一致：落盘在 Hub，前端只取结果文件/记录）。
- PRODUCT.md 第 430 行「媒体不经过浏览器」例外继续适用（实时音视频流），但录音/抓包/CDR 为服务端产物、前端仅取结构化结果，与「文件传输」语义一致。
- 视频驱动复用 `vidbridge`/`vidsrc` 与音频 `ausrc`/`auplay` 同构机制，不重复造抽象。
- 缺陷收口不引入破坏性变更，向后兼容；SQL 子类归并、S3 单栏等为内部重构，不改变对外行为。
- 前端改动统一用设计 token，不硬编码 hex。
