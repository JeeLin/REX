# 0.70.2: 音视频增强 + 通话记录 + 录音 + 抓包 + 质量监控

## Context

M82a（0.70.0）打通 SIP 信令层；M82b（0.70.1）打通浏览器实时双向音频（原始 S16LE PCM 媒体通道）。本阶段在 M82b 的媒体通道基础上，补齐**通话可观测性与媒体能力**：浏览器侧实时视频、通话录音落盘与回放、SIP 信令抓包、通话记录（CDR）持久化、实时音视频质量监控（丢包率/延迟/抖动）。

本里程碑同时承载用户确认的**缺陷池全量收口**：M82c 之前 `docs/BUGS.md` 累积的 9 条遗留 bug（🔴×1 / 🟡×5 / 🟢×3，跨更新检查/审计/工作空间/文件/SQL/移动端/SIP 等模块）全部纳入本里程碑修复范围（见 `## Bugs`），缺陷池已清空。

版本类型：minor（新增媒体可观测性功能 + 缺陷修复，向后兼容，无破坏性变更）

> 注：M82d（0.70.3）是整个代码库的质量收口里程碑（测试补全 + 文档重写 + 全量 review/优化 + 压测）。本里程碑已按用户决策先行并入缺陷池 bug，M82d 不再重复纳入这些项。

## 产品边界

### 本阶段做什么
- **浏览器实时视频（框架层）**：新建 `vidbridge` 视频驱动桥（与 `audio_bridge` 同构），媒体通道新增视频媒体类型（kind=2，原始 RGBA 像素帧），前端 `<canvas>` + getUserMedia 采集 + 开关。baresip 本机编译无视频编解码模块，端到端真视频需重建 baresip（超出本里程碑）；框架层已打通，单测覆盖编解码 round-trip 与隧道帧路由。
- **通话录音**：Hub 侧在通话建立后捕获媒体帧（音频 PCM / 视频帧）落盘为 mp3 / wav（复用 baresip aufile 或媒体帧捕获），前端提供回放器（进度/暂停/下载）。
- **信令抓包**：UA₁/UA₂ 两侧 SIP 报文捕获（baresip 报文日志钩子），导出为 pcap，前端回看/下载。
- **通话记录 CDR**：每通电话的起止时间/对端/时长/状态（呼叫/接听/挂断/未接）持久化（SQLite），前端表格（筛选/排序/详情），关联录音与抓包。
- **音视频质量监控**：实时采集丢包率、端到端延迟、抖动（baresip RTP 统计回调 / RTCP），前端可视化展示（通话中实时指标卡片）。
- **缺陷收口**：9 条遗留 bug 按 🔴→🟡→🟢 顺序修复（见 `## Bugs`）。

### 本阶段不做什么
- 不引入多用户、RBAC、企业协作。
- 不改变 Hub/Agent 版本一致模型。
- 不改动 M82b 已稳定的音频媒体通道契约（方向、kind 区分、PCM 格式）；视频仅扩展媒体类型，复用既有帧结构。
- 不改动信令层行为（register/dial/answer/hold/unhold/dtmf 不变）；SIP 资源「按名称管理 + 多账户切换」属 M82e，本阶段不做。
- 视频线上编码：默认维持原始边界，必要时再引入（与 M82b 音频不线上编码一致）。

## 子任务详细设计

### 1 浏览器实时视频

- **功能目标（实际落地，框架层）**：在 M82b 音频媒体通道基础上打通视频**框架层**。baresip **无内置视频编解码模块**（本机编译的静态库不含 vp8/vp9/av1/avcodec，且无 ffmpeg/libvpx/x264），端到端真视频需本地重建 baresip（超出本里程碑范围）。因此本子任务只打通**框架层**：新增 `vidbridge` 视频驱动桥（vidsrc/vidisp），媒体通道新增视频媒体类型（kind=2，原始 RGBA 像素帧），前端 `<canvas>` + getUserMedia 采集 + 开关，单测覆盖编解码 round-trip 与隧道帧路由。真视频联调留待后续（重建 baresip 或引入 WebCodecs/编解码器）。

  > 说明：里程碑初稿「复用 M82b 的 vidbridge/vidsrc 同构机制」前提**不成立**——彼时仅 `audio_bridge.rs` 存在，从未有视频桥。本子任务据此新建 `video_bridge.rs`，结构与 `audio_bridge.rs` 同构（vidsrc/vidisp 对标 ausrc/auplay；泵线程取帧对标音频 `rh` 回调）。
- **文件结构（实际）**：
  - `crates/rex-sip/src/video_bridge.rs`（新）：`VideoBridge`（`VideoFrame{rgba}` 双端队列 + `on_video` 回调 + 泵线程）、vidsrc/vidisp 注册与 allocator、vidframe RGBA 提取；`SipUaTrait` 增 `on_video` / `send_video`。
  - `crates/rex-common/src/sip_media.rs`（改）：`KIND_VIDEO=2`、`VideoPixFmt::Rgba`、`encode_video_frame`/`decode_video_frame`（`[fmt][w LE][h LE][rgba]`）。
  - `crates/rex-sip/src/baresip_ua.rs`（改）：`ensure_runtime` 注册视频驱动；`CALL_ESTABLISHED` 挂 vidisp 到 call。
  - `crates/rex-hub/src/sip_ws.rs` / `crates/rex-agent/src/agent_ws.rs`（改）：媒体帧路由增 kind=2 分支（下行原样推送、上行解码回灌 `send_video`）。
  - `packages/rex-console-web/src/api/sipMedia.ts`（改）：`encodeVideoFrame`/`decodeVideoFrame`/`paintRgbaToCanvas`/`SipVideo`；`api/sip.ts` 增 `onVideo` 回调 + `sendVideoFrame`，二进制帧首字节 kind 分流。
  - `packages/rex-console-web/src/features/sip/SipPage.vue`（改）：视频开关 + `<canvas>` 渲染 + i18n。
- **接口设计**：隧道二进制帧 `[4B ch_id][1B kind][payload]`，kind 复用（`KIND_MEDIA=1` 音频 PCM / `KIND_VIDEO=2` 视频 RGBA 像素），视频 payload `[fmt:u8][w:u16 LE][h:u16 LE][rgba...]`。Hub/Agent 两侧媒体路由共用同一 kind 解复用，方向隐含（浏览器↔Hub↔Agent↔baresip）。前端 `SipClient` 增 `onVideo(data)` 回调与 `sendVideoFrame(buf)`。
- **前端流程**：`call_state:active` → 点「开始视频」→ `startCamera` 取 getUserMedia 视频轨逐帧 `getImageData` 得 RGBA → `encodeVideoFrame` → `sendVideoFrame`（kind=2 上隧道）；下行 `onVideo` → `decodeVideoFrame` → `canvas.putImageData` 渲染。
- **测试标准**：`sip_media` 视频帧编解码 round-trip / 尺寸不符拒绝 / 未知 fmt 拒绝 / 过短拒绝 单测；`video_bridge` tx/rx round-trip / 畸形帧丢弃 / `on_video` 回调 / vidframe RGBA 重建 单测；`sip_ws`/`agent_ws` 视频媒体帧经 tunnel kind 无损路由单测（下行/上行）；前端 `sipMedia`/`sip` 视频帧编解码、kind 分流、`SipVideo` 渲染 单测。CI 难含真摄像头/解码器，联调以本地验证为准。
- **提交信息**：`feat: sip browser real-time video framework layer over media channel (0.70.2 #1)`

### 2 通话录音

- **功能目标**：Hub 在通话进行时捕获**下行（远端→本端）PCM 媒体帧**落盘为 WAV（16-bit PCM, 8kHz,
  单声道，与 M82b 媒体通道 `MEDIA_SAMPLE_RATE` 一致），通话结束写入 `<data_dir>/recordings/<cdr_id>.wav`
  并回填 CDR 的 `recording_url`；前端 CdrPage 详情已支持 `<audio>` 回放 + 下载。
- **实现要点（实际落地）**：
  - 媒体帧不经浏览器中转（与「文件传输不经过浏览器」一致）：Hub 在媒体边界直接 tap 落盘，前端只取
    结构化 `recording_url`。
  - 按 resource 开关（`/api/sip/recording/:id/start|stop`），但**按 call_id 分文件**——同一 resource
    多通电话各自独立录音，分别关联各自 CDR（CDR id 即 `cdr:{call_id}`）。
  - UA₁/UA₂ 两条下行链路都 tap：UA₁ 在 `on_rtp` 回调内，UA₂ 在隧道媒体帧分支；录音缓冲经
    `SipRecordingRegistry` 累积，通话 `Ended`/`Held` 时落盘。
  - 录制格式选 **WAV 而非 mp3**：避免引入 lame/ffmpeg 依赖，单用户自托管下浏览器原生 `<audio>`
    直接可播，且 WAV 头规范、便于单测校验（已写 `write_wav` 头部断言）。
- **文件结构**：
  - `crates/rex-hub/src/sip_recording.rs`（新）：`SipRecordingRegistry` 缓冲/落盘 + `write_wav` + `append_tunnel_media`
  - `crates/rex-hub/src/sip_recording_api.rs`（新）：`start`/`stop`/`GET /:id` 下载端点
  - `crates/rex-hub/src/sip_ws.rs`（媒体下行 tap + `CdrTracker` 调 `begin_call`/`finalize_call`）
  - `crates/rex-hub/src/app.rs`/`lib.rs`/`rex-hub.rs`（注册 `sip_recording` + 路由 + AppState 字段）
  - `packages/rex-console-web/src/api/sip.ts`（`recordingApi`）、`features/sip/SipPage.vue`（录音开关）
- **接口设计**：`POST /api/sip/recording/:id/start|stop`、`GET /api/sip/recordings/:id`（WAV 下载，
  `Content-Type: audio/wav`，支持 `?token=` 鉴权，与 capture 下载同款）。`recording_url` 写入 CDR。
- **前端流程**：SIP 页工具栏 → 开始录音（按 resource 开启，按 call 分文件落盘）→ 停止 → CDR 详情
  经 `recording_url` 回放/下载。
- **测试标准**：`write_wav` 头部 magic/格式/数据长度单测；`SipRecordingRegistry` 仅开启且设当前通话时
  累积、落盘 URL 正确、二次 finalize 幂等返回 None 单测；`append_tunnel_media` 解码媒体帧并落盘单测；
  前端 `recordingApi` start/stop 单测。
- **提交信息**：`feat: sip call recording: hub capture to disk + web playback (0.70.2 #2)`

### 3 信令抓包

- **功能目标**：UA₁/UA₂ 两侧捕获 SIP 信令报文，导出 pcap，前端下载。
- **实现要点（实际落地）**：baresip v4.10 **无 pcap/siprtp 模块**，但**核心库内置报文追踪钩子**
  `sip_set_trace_handler`(`re_sip.h`)——每收/发一条 SIP 信令回调真实报文字节（带 TX/RX
  方向与端点）。据此：
  - **UA₁（Hub 本地直连，全局）**：`rex_sip::capture` 接 `sip_trace` 钩子，捕获**真实 SIP 信令字节**
    （Wireshark 可直接解析），挂在进程内唯一 baresip runtime，故为 Hub 全局（不按 resource 区分）。
  - **UA₂（Agent 链式路径）**：SIP 在远端、经隧道二进制帧回 Hub 时已重建为 `SipEvent` JSON，
    不能经 baresip 钩子抓；在 Hub 中继层按 resource 捕获其 JSON 并入同一 pcap。
  - 后端**不落盘**，停止/下载时才编码为 libpcap（`LINKTYPE_RAW`，包体 = 报文文本），满足「前端仅下载 pcap」。
- **文件结构**：
  - `crates/rex-sip/src/capture.rs`（新）：`sip_trace` 钩子 + `CapturedPacket` + `encode_pcap`
  - `crates/rex-sip/src/lib.rs`（注册 `capture` 模块）、`baresip_ua.rs`（`install_trace` 在 runtime 初始化后挂载）
  - `crates/rex-hub/src/sip_capture.rs`（合并 UA₁ 全局 + UA₂ 中继）、`sip_capture_api.rs`（`/start` `/stop` `/packets` `/pcap`）
  - `packages/rex-console-web/src/api/sip.ts`（`sipCaptureApi`）、`features/sip/SipPage.vue`（开始/停止 + 下载 pcap）
- **接口设计**：`POST /api/sip/capture/:id/start|stop`、`GET /:id/pcap`（下载，Content-Type
  `application/vnd.tcpdump.pcap`）、`GET /:id/packets`（JSON 快照）。pcap 为 libpcap 格式
  （链路类型 RAW=101，包体为 SIP 文本/JSON）。
- **前端流程**：SIP 页工具栏 → 开始抓包（全局开启 UA₁ 钩子 + UA₂ 中继记录）→ 停止 → 下载 .pcap。
- **测试标准**：`encode_pcap` 头部 magic / linktype / 包封装单测；`capture` registry 仅激活时记录单测；
  前端 `sipCaptureApi` start/stop/pcapUrl 单测。
- **提交信息**：`feat: sip signaling packet capture to pcap + web viewer (0.70.2 #3)`

- **功能目标**：每通电话持久化起止时间/对端/时长/状态；前端表格筛选/排序/详情，关联录音与抓包。

## 设计核对点

- 单用户、自托管定位不被破坏（视频/录音/抓包端点仍是单一用户本地浏览器 + 服务端，无多租户）。
- 不引入 RBAC/多用户/企业协作。
- 媒体通道复用 M82b 的 `[kind][payload]` 结构，视频仅扩展媒体类型，不破坏既有音频契约。
- 录音/抓包/CDR 数据不经浏览器中转原始流（与「文件传输不经过浏览器」一致：落盘在 Hub，前端只取结果文件/记录）。
- PRODUCT.md 第 430 行「媒体不经过浏览器」例外继续适用（实时音视频流），但录音/抓包/CDR 为服务端产物、前端仅取结构化结果，与「文件传输」语义一致。
- 视频驱动复用 `vidbridge`/`vidsrc` 与音频 `ausrc`/`auplay` 同构机制，不重复造抽象。
- 缺陷收口不引入破坏性变更，向后兼容；SQL 子类归并、S3 单栏等为内部重构，不改变对外行为。
- 前端改动统一用设计 token，不硬编码 hex。
