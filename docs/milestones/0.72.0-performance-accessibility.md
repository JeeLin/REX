# 0.72.0: 前端性能与可访问性优化

## Context

0.71.0 完成了国际化完善。项目所有核心功能已实现，前端 i18n 覆盖率达到 100%。

当前前端构建配置较为基础（`vite.config.ts` 仅有 `outDir`），未做代码分割优化。可访问性方面，0.53.0 已建立良好基础（skip-link、TabBar ARIA 模式、CommandPalette/ContextMenu/ConfirmDialog 完整 ARIA 支持），但侧边栏折叠按钮、环境树展开按钮缺少 `aria-expanded`，`prefers-reduced-motion` 完全未支持，移动端侧边栏缺少焦点陷阱。

本里程碑聚焦三个方向：构建性能优化、可访问性补全、TypeScript 配置加固。

版本类型：minor（完善现有功能）

## 产品边界

**做什么：**
- Vite 构建优化：手动 chunk 分割（CodeMirror、xterm 独立 chunk）、构建目标升级、产物体积分析
- 可访问性补全：侧边栏 aria-expanded、prefers-reduced-motion、移动端侧边栏焦点陷阱、Toast 角色分级、Dashboard 统计卡片 aria-live
- TypeScript 配置加固：开启 noUncheckedIndexedAccess、forceConsistentCasingInFileNames

**不做什么：**
- 不修改后端 API
- 不添加新的产品功能
- 不引入新的外部 UI 库（保持现有手写方案）
- 不改变现有用户可见行为

## 子任务详细设计

### 1 Vite 构建优化

- **功能目标**：优化前端构建产物的 chunk 分割策略，减小首屏加载体积；添加构建产物分析能力
- **文件结构**：
  - 修改 `packages/rex-console-web/vite.config.ts`
  - 修改 `packages/rex-console-web/package.json`（新增 devDependency：`rollup-plugin-visualizer`）
- **功能点**：
  - **手动 chunk 分割**：在 `build.rollupOptions.output.manualChunks` 中将 CodeMirror 7 个包（`@codemirror/*`）分到 `codemirror` chunk，xterm 2 个包（`@xterm/*`）分到 `xterm` chunk，Vue 生态（`vue`、`vue-router`、`vue-i18n`、`pinia`）分到 `vendor` chunk
  - **构建目标升级**：添加 `build.target: 'es2020'`，与 `tsconfig.json` 的 target 一致，允许 Vite 使用更现代的语法降级策略
  - **chunk 体积警告**：设置 `build.chunkSizeWarningLimit: 500`（KB），便于发现异常大的 chunk
  - **产物分析工具**：安装 `rollup-plugin-visualizer`，添加 `--analyze` script（`rollup-plugin-visualizer --open`），按需生成 `stats.html` 体积分析报告
- **测试标准**：
  - `bun run build` 成功，无 error
  - `stats.html` 可正确生成（通过 `bun run analyze` 验证）
  - 产物目录出现独立的 `codemirror-*.js`、`xterm-*.js`、`vendor-*.js` chunk
- **提交信息**：`feat: optimize vite build with manual chunk splitting and bundle analyzer`

### 2 可访问性补全

- **功能目标**：补全 0.53.0 遗留的可访问性缺口，提升屏幕阅读器和键盘用户的体验
- **文件结构**：
  - 修改 `packages/rex-console-web/src/layouts/AppLayout.vue`（aria-expanded、搜索 aria-label、移动端焦点陷阱、装饰 emoji aria-hidden）
  - 修改 `packages/rex-console-web/src/components/ToastProvider.vue`（Toast 角色分级）
  - 修改 `packages/rex-console-web/src/pages/Dashboard.vue`（统计卡片 aria-live）
  - 修改 `packages/rex-console-web/src/styles/base.css`（prefers-reduced-motion 媒体查询）
  - 修改 `packages/rex-console-web/src/features/workspace/TabBar.vue`（aria-controls）
- **功能点**：
  - **侧边栏折叠按钮**：添加 `aria-expanded` 属性，绑定到侧边栏折叠状态；添加 `aria-label`（i18n key: `layout.toggleSidebar`）
  - **侧边栏搜索输入框**：添加 `aria-label`（i18n key: `layout.searchResources`）
  - **环境树展开/折叠按钮**：添加 `aria-expanded` 属性，绑定到展开状态
  - **装饰 emoji 隐藏**：侧边栏区域标题中的 emoji（如 ★、●）添加 `aria-hidden="true"`
  - **移动端侧边栏焦点陷阱**：移动端侧边栏打开时，将焦点限制在侧边栏内（Tab/Shift+Tab 循环）；关闭时恢复焦点到汉堡按钮
  - **prefers-reduced-motion**：在 `base.css` 中添加 `@media (prefers-reduced-motion: reduce)` 查询，禁用页面过渡动画（`page-fade`、`page-slide`）、Toast 进入/离开动画、标签脉冲动画
  - **Toast 角色分级**：错误/警告类型使用 `role="alert"`（assertive），成功/信息类型使用 `role="status"`（polite）
  - **Dashboard 统计卡片**：统计值容器添加 `aria-live="polite"`，数据更新时屏幕阅读器可感知
  - **TabBar aria-controls**：每个标签的 `role="tab"` 添加 `aria-controls` 指向对应面板 ID；面板添加 `role="tabpanel"` 和 `id`
- **测试标准**：
  - 侧边栏折叠/展开时，`aria-expanded` 值正确切换
  - 移动端侧边栏打开后，Tab 键焦点不逃逸
  - `prefers-reduced-motion: reduce` 下无动画
  - Toast 通知根据类型使用正确的 ARIA 角色
  - 前端 type-check 和 lint 通过
- **提交信息**：`feat: complete accessibility improvements with reduced-motion, aria-expanded, and focus trap`

### 3 TypeScript 配置加固与清理

- **功能目标**：启用更严格的 TypeScript 编译选项，提前发现潜在 bug
- **文件结构**：
  - 修改 `packages/rex-console-web/tsconfig.json`
  - 修改受影响的源文件（启用新规则后修复编译错误）
- **功能点**：
  - **noUncheckedIndexedAccess**：开启后数组/对象索引访问返回 `T | undefined`，需修复由此产生的类型错误
  - **forceConsistentCasingInFileNames**：开启后确保 import 路径大小写一致
  - **修复编译错误**：启用上述规则后运行 `bun run type-check`，逐一修复产生的类型错误
- **测试标准**：
  - `bun run type-check` 通过（0 error）
  - `bun run lint` 通过
  - `bun run build` 通过
  - `bun run test` 通过
- **提交信息**：`chore: tighten TypeScript config with noUncheckedIndexedAccess`
