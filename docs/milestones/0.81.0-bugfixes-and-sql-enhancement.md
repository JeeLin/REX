# 0.81.0: Bug 修复与 SQL 操作界面增强

## Context

0.80.0 完成了前端界面设计与优化（CSS token 补齐、light 主题适配、弹窗动画、UI bug 修复）。本里程碑聚焦两个方向：清理累积的高影响 bug（SQLite 连接、Agent 部署、仪表盘路由、审计日志），以及提升 SQL 控制台操作体验。

当前 AGENTS.md 记录 8 个未修复 bug，其中 4 个影响核心工作流（SQLite 连接错误消息不明确、仪表盘 API 404、Agent 部署指南为空）。审计日志的 2 个 bug（操作值英文、详情无价值）虽非阻塞，但持续降低可信度。

版本类型：minor（新功能 + bug 修复）

**做什么**：

## 子任务详细设计

### 1 SQLite 错误消息结构化

- **功能目标**：SQLite 连接失败时返回用户可读的具体错误消息（如"文件不存在"、"权限不足"、"数据库被锁定"），而非通用的"连接失败"
- **文件结构**
  - 修改：SQLite 连接后端 handler（`ws_sqlite.rs`）— 错误消息结构化
  - 修改：SQLite 前端组件（`WorkspaceSqlite.vue`）— 错误面板样式优化
- **接口设计**
  - 后端：SQLite 连接失败返回结构化错误 `{ error: string, code: string }`，根据错误类型返回具体消息
  - 前端：连接失败时显示 ErrorState 组件，含错误描述和「重试」按钮
- **交互设计**
  - 连接失败：编辑器区域显示错误面板（红色图标 + 错误信息 + 重试按钮）
  - 错误类型映射：
    - 文件不存在 → "数据库文件不存在: {path}"
    - 权限不足 → "没有权限读取文件: {path}"
    - 数据库被锁定 → "数据库被其他进程锁定"
    - 其他错误 → "连接失败: {具体错误信息}"
- **后端流程**：SQLite connect handler 改用 `map_err` 包装错误，根据错误类型返回用户可读消息
- **测试标准**
  - 连接不存在的文件路径 → 前端显示"数据库文件不存在"错误
  - 连接权限不足的文件 → 前端显示"没有权限读取文件"错误
  - 连接被锁定的数据库 → 前端显示"数据库被其他进程锁定"错误
- **提交信息**：`fix(sqlite): provide structured error messages for connection failures`

- **交互设计**

  - Agent 列表中未部署的 agent 显示灰色「未配置」徽章，而非绿色「在线」
- **后端流程**：无（纯前端修复，或后端路由层修复重复前缀）
- **测试标准**
  - 仪表盘页面加载无 404 错误
  - 未部署 agent 显示正确状态
- **提交信息**：`fix(dashboard): correct API path duplication and agent status display`

### 4 审计日志操作值本地化 + 详情增强

- **功能目标**：审计日志操作列从英文改为中文；审计日志详情面板展示有意义的信息
- **文件结构**
  - 修改：审计日志前端组件 — 操作值翻译映射
  - 修改：审计日志 API — 详情包含更有价值的上下文信息
- **接口设计**
  - 操作值映射表：`create` → `创建`、`update` → `更新`、`delete` → `删除`、`connect` → `连接`、`login` → `登录`、`export` → `导出` 等
  - 日志详情增强：展示变更前后对比（如资源名修改：旧值 → 新值）、请求来源 IP、操作耗时
- **交互设计**
  - 操作列显示中文标签（彩色徽章：创建=绿色、更新=蓝色、删除=红色）
  - 详情面板：结构化展示变更内容，不再只是原始 JSON
- **后端流程**：审计日志写入时额外记录 `old_value`/`new_value` 对比字段（或在查询时关联）
- **测试标准**
  - 审计日志操作列全部显示中文
  - 日志详情面板展示有意义的变更信息
- **提交信息**：`fix(audit): localize operation labels and enhance log details`

### 5 SQL 行内编辑与单元格编辑器

- **功能目标**：参考 Navicat，SQL 查询结果支持双击行内编辑，修改后可提交到数据库
- **文件结构**
  - 修改：SQL 结果表格组件（`SqlResultTable.vue` 或等效）— 行内编辑支持
  - 新增：单元格编辑器组件（`CellEditor.vue`）— 根据列类型渲染对应编辑控件
- **接口设计**
  - 单元格编辑器根据列类型自动适配：
    - 数字类型：数字输入框
    - 文本类型：文本输入框
    - NULL 值：特殊处理（NULL toggle + 值输入）
    - 枚举/布尔：下拉选择
  - 提交编辑：生成 `UPDATE ... WHERE pk = ...` 语句并执行
  - 乐观更新：前端先显示修改值，提交失败后回滚
- **交互设计**
  - 双击结果表格单元格 → 进入编辑模式（高亮边框）
  - 编辑态：输入框覆盖单元格，回车提交，Esc 取消
  - 修改过的单元格显示蓝色标记（小三角指示器，类似 Excel）
  - 底部工具栏显示「N 行已修改」+ 「提交变更」按钮
  - 提交后 Toast 提示「已更新 N 行」
- **后端流程**：复用现有 SQL 执行 API，前端生成 UPDATE 语句
- **测试标准**
  - 双击数字/文本单元格进入编辑，修改后回车提交
  - 无主键的查询结果禁用行内编辑
  - 提交失败时回滚显示原值并提示错误
- **提交信息**：`feat(sql): add inline cell editing for query results`

### 6 SQL 批量操作与数据维护

- **功能目标**：SQL 结果表格支持批量选中行操作（删除、导出选中行）；库表结构树支持右键「清空表」「删除行」快捷操作
- **文件结构**
  - 修改：SQL 结果表格组件 — 复选框列 + 批量操作工具栏
  - 修改：库表结构树右键菜单 — 新增数据维护菜单项
  - 新增：批量操作确认弹窗
- **接口设计**
  - 批量选择：结果表格左侧增加复选框列，支持全选/反选
  - 批量操作工具栏：选中 N 行后底部显示操作栏（删除选中行、导出选中行、取消选择）
  - 右键菜单扩展：
    - 表节点新增：「清空表数据」（TRUNCATE）、「删除表」（DROP TABLE，需二次确认）
  - 删除操作生成 `DELETE FROM ... WHERE pk IN (...)` 语句
- **交互设计**
  - 复选框列：表头全选 checkbox + 每行 checkbox
  - 批量操作栏：选中行数 + 操作按钮，底部固定定位
  - 危险操作（清空/删除）弹出 ConfirmDialog，需输入表名确认
- **后端流程**：复用现有 SQL 执行 API
- **测试标准**
  - 选择多行 → 批量删除 → 确认 → 数据被删除
  - 右键表节点 → 清空表数据 → 确认 → 表数据清空
  - 无主键查询结果禁用批量删除
- **提交信息**：`feat(sql): add batch operations and table data maintenance`

## 设计核对点

1. **SQLite 错误处理**：所有连接失败场景（文件不存在、权限不足、数据库锁定）均在前端有明确提示
2. **API 路径一致**：仪表盘及相关页面无重复前缀的 API 调用
3. **Agent 状态准确**：未部署 agent 不显示为在线
4. **审计日志可读**：操作值全中文，详情包含有意义的变更信息
5. **SQL 编辑体验**：行内编辑支持主流数据类型，编辑→提交→反馈流程完整
6. **批量操作安全**：危险操作需二次确认，无主键查询禁用破坏性操作
7. **向后兼容**：不破坏现有 SQL 查询结果的只读模式
