# 0.70.1: 浏览器实时双向音频（Opus-over-WebSocket 媒体通道）

## Context

M82a（v0.70.0）完成 SIP 信令层：register/dial/answer/hangup/hold/unhold/dtmf + 事件流，Hub/Agent 共用 baresip FFI 当 UA₁/UA₂，前端 `features/sip/` 拨号盘 + 通话状态。但音频流（RTP）在 M82a 仅留 `SipUaTrait::on_rtp` 空桩接口。

本阶段打通**浏览器实时双向音频**：Hub（或 Agent UA₂）侧终止 RTP，将 PCM 编码为 Opus，经 WebSocket 媒体通道实时推流到浏览器；浏览器用 Web Audio 解码播放，麦克风经 `getUserMedia` 采集、反向编码回传，实现浏览器与对端**实时双向**通话（满足「时时对话」）。

**产品原则例外说明**：PRODUCT.md 第 430 行规定「数据在 Hub/Agent/远端之间传输，不经过浏览器」——音频媒体是此原则的**显式例外**（DEVELOPMENT.md M82b 已确认：用户明确要求浏览器实时听/说，媒体为实时流而非批量文件传输，与「文件传输不经过浏览器」的初衷不冲突）。本里程碑所有信令/控制/媒体帧仍经 Hub/Agent 服务端中转，浏览器只作为媒体端点，不接触远端 SIP 服务器。

版本类型：minor（SIP 功能的延续增强，向后兼容，无破坏性变更）

## 产品边界

### 本阶段做什么
- baresip 音频接管：在 baresip 事件线程内从 `call_audio()`/`auframe` 抽取接收 PCM、向发送侧喂 PCM（接管默认 audio 设备，避免依赖系统 alsa/coreaudio）；接 `on_rtp` 钩子回调。
- Hub 侧 RTP→Opus 编码管线（发送链路）：从 UA 抽取 PCM → Opus 编码 → 媒体帧经 `/ws/sip` 推浏览器。
- `/ws/sip` 媒体通道：新增 binary 媒体帧协议（与现有文本信令帧区分），支持 Hub→浏览器下行 Opus 帧 + 浏览器→Hub 上行麦克风 Opus 帧。
- Agent UA₂ 媒体转发：隧道 binary 帧中区分「媒体」与「信令」，媒体帧经现有 `agent_ws.rs` 隧道回 Hub（复用 channel_id 多路复用，不新造隧道）。
- 前端 Web Audio 播放 + 麦克风采集（`getUserMedia`）+ Opus 解码（WebCodecs / opus 解码库），通话中可听可说。
- 延迟/回声基础优化（jitter buffer、回声抑制开关）+ 端到端联调（可听可说）。

### 本阶段不做什么
- 不实现 CDR/录音/信令抓包/展示图（属 M82c / 0.70.2）。
- 不改动信令层行为（M82a 已稳定的 register/dial/.../事件流保持不变）。
- 不改变 Hub/Agent 版本一致模型。
- 不引入多用户/ RBAC / 企业协作。

## 子任务详细设计

### 1 `crates/rex-sip` 音频链路（自注册 baresip 音频驱动方案）

- **功能目标**：经 baresip 公开 FFI 注册一对**自定义音频驱动**——`ausrc`（发送源：baresip 取 PCM 去编码发对端）+ `auplay`（接收播放器：baresip 把远端解出 PCM 交给我们），挂在 account 上（`audio_set_source`/`audio_set_player`）。接收侧每帧 PCM 经 `on_rtp` 回调上抛；发送侧新增 `send_audio` 把浏览器麦克风 PCM 喂回 baresip 发送链路。opus 作线上编解码依赖。**不走** `call_audio()` 内部私有帧（`include/baresip.h:1429` 仅 forward-declare `struct audio`，公开头不暴露帧抽取接口，跨版本易碎），改用稳定的 `ausrc`/`auplay` 驱动回调（aubridge 模块同构机制）。
- **文件结构**：
  - `crates/rex-sip/build.rs`（bindgen `allowlist` 增加 `ausrc`/`auplay`/`audio`/`aufmt` 类型与 `ausrc_register`/`auplay_register`/`audio_set_source`/`audio_set_player`/`auframe_*` 访问函数，使驱动注册与 PCM 搬运可用）
  - `crates/rex-sip/src/audio_bridge.rs`（**新模块**：定义 `extern "C"` 的 `ausrc_read_h`/`auplay_write_h` 回调 + `ausrc_alloc_h`/`auplay_alloc_h`；`register()` 调 `baresip_ausrcl()`/`baresip_auplayl()` 注册；用 `Box<AudioBridge>` 作 `void* arg` 在 C 回调与 Rust 间搬运；PCM 经 `Arc<Mutex<RingBuf>>` 跨线程；回调必须同步返回、绝不 await/阻塞）
  - `crates/rex-sip/Cargo.toml`（加 `opus = { workspace = true }`；workspace.dependencies 加 `opus`）
  - `crates/rex-sip/src/lib.rs`（`SipUaTrait` 改 `on_rtp` 为接收钩子 + 新增 `async fn send_audio(&self, pcm: Vec<i16>) -> Result<()>`；`on_rtp` 默认实现移除 no-op 注释，改为可注册；`AudioFormat` 描述 srate/ch/fmt）
  - `crates/rex-sip/src/baresip_ua.rs`（通话建立后 `audio_set_source`/`audio_set_player` 挂 `audio_bridge`；`send_audio` 经 mqueue 主线程序列化，把 PCM 压入 `ausrc` 的 ring buffer；复用 M82a 的 mqueue 单线程模型）
  - `crates/rex-sip/src/mock.rs`（Mock 记录 `send_audio` 调用，便于 handler 单测）
- **接口设计**：
  ```rust
  // 接收：baresip `auplay_write_h` 回调内每帧 PCM 调用（AUFMT_S16LE i16 LE，srate/ch 由 auframe 给出）
  fn on_rtp(&self, cb: impl FnMut(&[u8] /*pcm i16 LE*/) + Send + 'static);  // 沿用 M82a 钩子签名
  // 发送：浏览器麦克风 PCM 回传
  async fn send_audio(&self, pcm: Vec<i16>) -> anyhow::Result<()>;
  ```
  baresip 音频采样约定：内部 PCM 统一 `AUFMT_S16LE`（signed 16-bit LE，对应 Rust `i16`），声道/采样率由协商的 `auf` 参数决定（M82b 默认 8000Hz mono）；opus 仅作 WebSocket 线上编码。
- **后端流程**：`register()` 在 baresip 运行期把 `rex_ausrc`/`rex_auplay` 两驱动注册进全局 `baresip_ausrcl()`/`baresip_auplayl()`；通话 `BEVENT_CALL_ESTABLISHED` 后 `audio_set_source(call_audio(call), "rex_ausrc", dev)` / `audio_set_player(... "rex_auplay" ...)`。**关键机制（已核对 aubridge 源码）**：baresip 把**自身内部** `ausrc_read_handler`/`auplay_write_handler` 作为 `rh`/`wh` 传给我们的 `alloch`，故我们的 `alloch` 只负责分配 `st` 并把 baresip 的 `rh`/`wh` 存进 `st`；真正拿到原始 PCM 的是**同名 device 的泵线程**——它按固定 ptime（20ms）周期调 `st->wh(auf, st->arg)`（接收侧，远端 PCM 流入）/ `st->rh(auf, st->arg)`（发送侧，取 PCM 去编码），我们的 RX/TX ring 夹在 device 与 WS 编码器之间：接收帧经 `auframe_init` 构造后由泵线程推入 RX ring（独立任务取走 → Opus 编码 → `on_rtp` 上抛）；`send_audio` 经 mqueue 把麦克风 PCM 压入 TX ring，泵线程 `ausrc_read_h` 取走去编码发对端。**此 device-bridge 模式与 baresip `aubridge` 模块同构，是拿到原始 PCM 唯一稳定的方式**；视频侧 `vidsrc`/`vidisp`/`vidbridge` 与之完全同构（已核实），后续 0.70.3 浏览器视频直接复用本抽象，无返工。M82a 的「单例运行时 + mqueue 主线程序列化 + 无跨线程竞争」模型继续适用。
- **FFI 不透明句柄约定（已核对 baresip 源码，稳定性依据）**：baresip 核心把 `ausrc_st`/`auplay_st` 当**完全不透明指针句柄**——各音频模块（aubridge/alsa/aufile…）各自重定义该结构体、自行 `mem_zalloc(sizeof(*st))` 并填 `dev/prm/rh/arg`；核心只在 `ausrc_alloc`/`auplay_alloc` 后持有 `st` 指针、管生命周期与析构 `mem_deref`，**永不解引用 `st` 的字段**（已 grep `src/*.c` 确认 0 处 `st->rh/prm/dev` 解引用）。生成的 bindings 中 `ausrc_st`/`auplay_st` 被 bindgen 收紧为**零大小不透明体**；故 Rust 侧 `alloch` 回调**不可** `mem_zalloc(size_of::<ausrc_st>())`（会得到 0 字节）。正确做法：Rust 侧 `#[repr(C)]` 镜像 aubridge 字段序（`dev: *mut c_void, prm: ausrc_prm, rh: ausrc_read_h, arg: *mut c_void`），用 `size_of::<RustAusrcSt>()` 分配，`stp` 经 `*mut c_void` 强转；`dev` 置 null（不接 aubridge device 机制，改用 ring buffer），`rh`/`wh` 填我们的 C 回调，`arg` 填 `Box<AudioBridge>` 裸指针。此路径与公开稳定 API 一致、布局由我们精确控制，跨 baresip 版本不依赖 bindgen 内部行为。
- **测试标准**：`audio_bridge` 的 ring buffer 进出单测（C 回调→ring→取出字节一致）；Mock `send_audio` 记录调用（`mock.rs`）；baresip 真链路需真 SIP server + 音频设备模拟（联调验证，CI 不覆盖）。`cargo build`/`cargo test` 全绿。
- **提交信息**：`feat: rex-sip audio bridge: ausrc/auplay driver + send_audio (0.70.1 #1)`

### 2 Hub `/ws/sip` 媒体通道

- **功能目标**：`/ws/sip` 复用同一 WebSocket，新增 binary 媒体帧（与文本信令帧区分），下行 Opus 帧推浏览器、上行麦克风 Opus 帧收浏览器。
- **文件结构**：
  - `crates/rex-hub/src/sip_ws.rs`（新增 `handle_sip_session`/`handle_agent_sip` 媒体分支：注册 `on_rtp` 回调 → Opus 编码 → `Message::Binary` 推浏览器；收 `Message::Binary` 上行帧 → Opus 解码 PCM → `ua.send_audio`）
  - 新增媒体帧类型（line 格式区分）：binary 帧首字节或 JSON 包装 `{type:"media", dir:"down"|"up", payload:<base64/raw opus>}`
- **接口设计**（媒体帧，复用 `/ws/sip`，与信令 `ClientMsg`/`ServerMsg` 文本帧并存）：
  - Hub→浏览器下行：`Message::Binary(opus_frame)`（或 `{type:"sip.media", dir:"down", payload: <base64 opus>}` 文本包，优先 binary 降低开销）
  - 浏览器→Hub 上行：`Message::Binary(opus_mic_frame)`
  - 鉴权复用现有 JWT query token。
- **后端流程**：`handle_sip_session` 注册 `on_rtp` → Opus 编码 → `ws_sink.send(Binary)`；前端 Binary 帧 → Opus 解码 → `ua.send_audio(pcm)`。`handle_agent_sip`（Agent 链式）把媒体帧经隧道 binary 帧（channel_id 前缀 + `media` 标记）转发给 Agent UA₂，Agent UA₂ 的 `on_rtp` 回传同样经隧道回 Hub。
- **测试标准**：`sip_ws.rs` 用 Mock `SipUa` 测 `on_rtp` 回调触发下行帧、`send_audio` 被上行帧调用（handler 单测）；opus 编解码 round-trip 单测。
- **提交信息**：`feat: hub /ws/sip media channel: opus down/up over binary frames (0.70.1 #2)`

### 3 Agent UA₂ 媒体转发

- **功能目标**：Agent 内 UA₂ 接管音频后，媒体帧经现有 `agent_ws.rs` 隧道（channel_id 多路复用 + binary 帧）回 Hub，与信令帧共用通道但用 `media` 标记区分。
- **文件结构**：
  - `crates/rex-agent/src/agent_ws.rs`（`run_sip_ua2` 注册 `on_rtp` → 经 `data_tx` 隧道发媒体 binary 帧；收隧道 media 帧 → `ua.send_audio`；复用 M82a 的数值 `AGENT_CHANNEL_SEQ`）
- **接口设计**：隧道 binary 帧 `[4B channelId][1B kind][payload]`，`kind=0` 信令（SipEvent JSON）/ `kind=1` 媒体（Opus/PCM）。沿用 M82a 隧道，仅扩展 kind 字节。
- **后端流程**：Agent `run_sip_ua2` 起 UA₂ 并注册 `on_rtp`，媒体帧经 `data_tx` 发隧道；Hub `handle_agent_sip` 区分 kind=1 帧 → Opus 编码推浏览器；上行浏览器帧 → 隧道 kind=1 → Agent `ua.send_audio`。
- **测试标准**：Agent `run_sip_ua2` 媒体帧经隧道进出单测（mock 隧道 channel，断言 media kind 正确标记 + 字节经 data_tx 进出）。
- **提交信息**：`feat: agent UA2 media relay over channel-multiplexed tunnel (0.70.1 #3)`

## 设计核对点

- 单用户、自托管定位不被破坏（音频端点仍是单一用户本地浏览器，无多租户）。
- 不引入 RBAC/多用户/企业协作。
- **PRODUCT.md 430 行「媒体不经过浏览器」的显式例外**：本里程碑浏览器作为实时音频端点（用户明确要求可听可说），所有帧仍经 Hub/Agent 服务端中转，浏览器不接触远端 SIP 服务器，与「文件传输不经过浏览器」初衷不冲突——此为 DEVELOPMENT.md M82b 已确认的例外，步骤2 核对时以此为准，不视为违反产品边界。
- 信令层（M82a 稳定的 register/dial/.../事件流）行为不变，本里程碑仅增媒体通道。
- 音频链路复用 M82a 的 baresip 单例运行时 + mqueue 主线程序列化模型，send_audio 同样经 mqueue 串行化，避免跨线程竞争（延续 M82a 线程安全结论）。
- **音频接管走 baresip 公开 `ausrc`/`auplay` 驱动回调**（`ausrc_register`/`auplay_register` + `audio_set_source`/`audio_set_player`），不碰 `call_audio()` 私有内部结构（公开头仅 forward-declare），跨 baresip 版本稳定；C 回调（`auplay_write_h`/`ausrc_read_h`）必须同步返回、绝不 await/阻塞，PCM 经 ring buffer 与独立编码任务解耦。
- **媒体抽象媒体无关**：`on_rtp`/`send_audio` 与隧道媒体帧以 `MediaFrame{kind:Audio|Video, payload}` 承载，不写死 Opus；本里程碑仅实装 Audio 分支，视频（vidbridge/vidsrc 同构机制，浏览器侧 WebCodecs+`<video>`）留作后续里程碑（如 0.70.3），复用本通道与 Hook 模式、无返工。
- Agent 媒体转发复用现有 `agent_ws.rs` 隧道（channel_id 多路复用 + binary 帧，仅扩展 kind 字节区分媒体/信令），不新造隧道。
- 前端改动统一用设计 token，不硬编码 hex。
- opus 编解码：线上用 opus（带宽友好），内部 baresip↔Rust 边界统一 `AUFMT_S16LE` i16 LE PCM（与 baresip 音频管线对齐）。
