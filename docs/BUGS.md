# 缺陷池

| 提出版本 | 优先级 | 标题 | 来源 | 描述 |
|----------|--------|------|------|------|
| M80 | 🔴 | 版本更新检查会下载比当前更旧的版本（降级） | 用户反馈 | 当前运行 0.68.0，GitHub 的「Latest」Release 为 0.65.4，更新检查仍提示 `UPDATE_AVAILABLE` 并下载 0.65.4 覆盖当前版本。`crates/rex-hub/src/update_checker.rs` 仅用 `releases/latest` 接口且只判断 `latest_version == current_version`，未做语义化版本比较——只要两者不相等就下载，导致当 GitHub「Latest」标签指向比当前更旧的版本时，会把正在运行的二进制降级到旧版。需改为：用 `/releases` 列表取 tag 中真正最高的语义化版本（或确认 latest 严格大于 current 才更新）。 |
| M80 | 🟡 | 审计日志分页对用户不可见 / 功能单薄 | 用户反馈 | 后端 `query_audit_log`（`crates/rex-hub/src/db.rs:175-180`）与前端 `AuditLogPage.vue` 其实已实现 limit/offset 分页链路（前端 pageSize=50、currentPage、totalPages、上/下一页按钮），但分页控件被 `v-if="totalPages > 1"` 包裹（`AuditLogPage.vue:425`），只要筛选结果 ≤ 50 条翻页条与「共 N 条」提示就完全不渲染，用户看到的是「没有分页」。此外 UI 只有 上一页/下一页 + `x/y`，没有每页条数选择、跳页、总数提示。需改为：始终显示分页控件（数据少时显示「共 N 条，无需翻页」），并补充每页条数切换与明确的总数信息；同时建议后端 `ORDER BY time DESC, id DESC` 增加稳定二级排序。 |
| M80 | 🟡 | 分栏不会作用于当前聚焦的 pane，而是固定作用于默认叶子 | 用户反馈 | 状态栏底部的分栏按钮（`WorkspacePage.vue:453-454` 的 ⬌/⬍）和 `Ctrl+\` / `Ctrl+Shift+\` 快捷键调用 `splitHorizontal()`/`splitVertical()` 不带参，退回使用 `activePaneId.value`。而 `activePaneId` 仅在 `.ws-pane` 根 div 的 `@click` 时更新（`features/workspace/PaneLeaf.vue:33`），没有 `focus`/`pointerdown`/`focusin` 跟踪。xterm 终端连接成功后会 `terminal.focus()`（`features/terminal/WorkspaceTerminal.vue:323`），点击终端内部不会冒泡到 `.ws-pane` 的 click（xterm 容器还有 `@click.stop`），导致 `activePaneId` 永远停在初始化值（第一个叶子 `root.value.children[0]`，`composables/usePaneLayout.ts:90`），于是状态栏/快捷键分栏永远作用在默认那片 pane，而非用户当前聚焦的 pane。注意：pane 头部自带的 ⬌/⬍ 按钮因为直接传 `leaf.id`（`PaneLeaf.vue:69-70`）所以对、能正确分栏——这也佐证了根因在 `activePaneId` 的更新时机而非 `splitPane` 本身。修复：让"当前聚焦/最近交互的 pane"可靠地写回 `activePaneId`（例如监听 `focusin`/在交互入口处更新，或让 `splitHorizontal/Vetical` 优先取最近聚焦的 leaf）。 |
| 0.69.0 | 🟡 | S3 文件管理左右双栏无意义，应合并为单栏，移动操作移至右键菜单 | 用户反馈 | S3 资源（`features/files/FilesPage.vue` 等）当前仍用 SFTP 风格的左右双栏布局，但 S3 是单 bucket/prefix 模型，双栏没有意义，应合并成单栏。移动文件操作不应放在双栏逻辑里，应加到文件项的右键上下文菜单（`ContextMenu`）上。 |
| 0.69.0 | 🟢 | 手机端不需要快捷键按钮 | 用户反馈 | 移动端（响应式/手机布局）不应显示桌面风格的快捷键按钮（如快捷键面板入口、状态栏快捷键提示等），在触屏上没有意义，应隐藏或改为触屏友好交互。 |
| 0.69.0 | 🟢 | 手机端仪表盘 Quick Connect 仍是两列，其他内容已是一列 | 用户反馈 | 移动端仪表盘中，Quick Connect 区域仍保持两列布局，而仪表盘其他内容已正确折叠为单列；应统一为单列（与仪表盘其余部分一致）。 |
